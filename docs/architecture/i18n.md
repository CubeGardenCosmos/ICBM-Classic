# 国际化（i18n）

依据 [ADR 0005](../decisions/0005-i18n-json-and-arabic-shaping.md)。实施阶段 S8（最后执行）。S2–S7 期间只维护 `en_us.json`。

## 1. 文件与语言

| 语言码（文件名） | 语言 | 要求 | 来源 |
| --- | --- | --- | --- |
| `en_us.json` | 英语（美国） | 源语言，键的唯一事实源 | 1.12 `en_US.lang` 迁移 + 新增 |
| `zh_cn.json` | 简体中文 | 必需，100% | 1.12 `zh_cn.lang` 迁移后补全 |
| `fr_fr.json` | 法语（法国） | 必需，100% | 新翻译 |
| `de_de.json` | 德语（德国） | 必需，100% | 1.12 `de_DE.lang` 迁移后补全 |
| `ja_jp.json` | 日语 | 必需，100% | 新翻译 |
| `ar_sa.json` | 阿拉伯语 | 必需，100%；**生成文件** | 源 `src/i18n/ar_sa.source.json` 经 `shapeArabic` 生成 |
| `es_es`、`ko_kr`、`pt_br`、`ru_ru` | 旧语言 | 尽力保留，不保证完整 | 1.12 迁移 |

路径：`src/main/resources/assets/icbmclassic/lang/<code>.json`。文件名必须全小写。编码 UTF-8 无 BOM，2 空格缩进，键按字母序排列（由 `scripts/check_lang.py --fix-order` 整理）。

## 2. 键命名规则

| 类别 | 格式 | 例子 |
| --- | --- | --- |
| 方块 | `block.icbmclassic.<方块ID>` | `block.icbmclassic.radar_station` |
| 物品 | `item.icbmclassic.<物品ID>` | `item.icbmclassic.condensed_missile` |
| 实体 | `entity.icbmclassic.<实体ID>` | `entity.icbmclassic.anti_ballistic_missile` |
| 创造标签 | `itemGroup.icbmclassic.main` | |
| 爆炸物名称（组合用） | `icbmclassic.explosive.<爆炸物ID>` | `icbmclassic.explosive.condensed` = "Condensed" |
| 形态模板 | `icbmclassic.form.explosive|missile|grenade|bomb_cart|bomblet` | `"%s Missile"` |
| GUI | `icbmclassic.gui.<机器>.<元素>` | `icbmclassic.gui.radar_station.detection_range` |
| 提示文本 | `icbmclassic.tooltip.<主题>.<细节>` | |
| 聊天/状态消息 | `icbmclassic.message.<主题>.<细节>` | |
| 无线电 | `icbmclassic.radio.<细节>` | |
| 命令 | `icbmclassic.command.<子命令>.<结果>` | 迁移自 `command.icbmclassic:icbm.blast.triggered` |
| 能量 | `icbmclassic.energy.<细节>` | |
| 死亡消息 | `death.attack.icbmclassic.<伤害类型>`（及 `.player` 变体） | |
| 效果 | `effect.icbmclassic.<效果ID>` | |
| 声音字幕 | `subtitles.icbmclassic.<声音>` | |
| 配置（不显示，仅保留以便将来做配置界面） | 不迁移 | 1.12 `config.icbmclassic:*` 全部丢弃 |

**爆炸物平铺化物品的名称**：datagen 为每个 `<ex>_missile` 等生成独立键（如 `item.icbmclassic.condensed_missile`），值由“爆炸物英文名 + 形态英文”拼成（如 "Condensed Missile"）。其他语言**逐条翻译**，不用运行时模板拼接（不同语言语序不同，例如日语“凝縮ミサイル”、阿拉伯语“صاروخ مكثف”名词在前）。

## 3. 占位符

- 允许：`%s`、`%d`、`%1$s`、`%2$s`…、`%%`。
- 译文的占位符**集合**必须与英文一致；需要调整语序时用位置占位符 `%1$s`。`check_lang.py` 检查：把 `%s` 依次编号后，比较两边的编号集合。
- 颜色代码（`§a` 等）：禁止出现在语言文件中。颜色用 `Component.withStyle(ChatFormatting.X)` 在代码里加。1.12 文件中的 `§` 代码在迁移时删除并记录到 S8.01 证据。

## 4. en_us 的两个来源与合并

- **datagen 部分**：`ICBMLanguageProvider extends FabricLanguageProvider`（client 源集 datagen），只生成方块/物品/实体/爆炸物名称/创造标签（可从注册表与 `ExplosiveRegistry` 推导的键），输出到 `src/main/generated/assets/icbmclassic/lang/en_us.json`。
- **手写部分**：`src/main/resources/assets/icbmclassic/lang/en_us.json`（GUI、消息、提示等）。
- 两个文件都会进入 jar，同一路径冲突。**规则**：`processResources` 中把两个 `en_us.json` 合并成一个（手写覆盖生成；出现同键不同值时构建失败并打印键名）。S2.10 实现 Gradle 任务 `mergeLang`，`processResources` 依赖它，合并结果写到 `build/generated/lang/en_us.json` 并从两个源目录排除原文件。
- 其他语言只有手写文件（翻译者需要看到全部键，所以 S8 先用 `scripts/check_lang.py --dump-en` 输出合并后的英文全集给翻译步骤）。

## 5. 阿拉伯文（从右到左与字形整形）

已核实事实（2026-10-10）：26.3 `net.minecraft.client.resources.language.FormattedBidiReorder` 使用 `com.ibm.icu.text.Bidi`/`BidiRun` 做双向重排，**不调用 `com.ibm.icu.text.ArabicShaping`**；26.3 客户端自带 `com.ibm.icu:icu4j:78.3`。

做法：

1. 翻译者编辑 `src/i18n/ar_sa.source.json`（普通阿拉伯字母，逻辑顺序，与其他语言文件同格式）。
2. Gradle 任务 `shapeArabic`（S8.09 实现，`buildSrc` 或 `build.gradle` 内联 `JavaExec`/直接用 Groovy 调 ICU）：
   ```groovy
   // 伪代码：对每个值
   def shaper = new com.ibm.icu.text.ArabicShaping(
       com.ibm.icu.text.ArabicShaping.LETTERS_SHAPE | com.ibm.icu.text.ArabicShaping.LENGTH_GROW_SHRINK)
   String shaped = shaper.shape(value)   // 只整形，不重排；重排交给游戏的 Bidi
   ```
   构建脚本依赖 `com.ibm.icu:icu4j:78.3`（`buildscript { dependencies { classpath ... } }`）。
3. 占位符 `%s`、`%1$s` 与拉丁字母、数字原样保留（ICU 整形不改变它们）。
4. 输出 `src/main/generated/assets/icbmclassic/lang/ar_sa.json`；`check_lang.py` 对 `ar_sa` 检查生成文件，同时检查源文件键集合。
5. `ar_sa.json` 文件头无法写注释（JSON），在 `src/i18n/README.md` 中说明“生成文件，勿手改”。
6. 人工门禁 S8.12：在 26.3 客户端选择 العربية，截图核对物品名、GUI、提示文本连写与方向。若发现原版已正确连写（即双重整形导致错误），新建 ADR 撤销预整形。

字体：26.3 默认字体（含 Unifont 回退）覆盖阿拉伯字母及呈现形式 B（U+FE70–U+FEFF）——**待验证**，由 S8.12 截图确认。

GUI 布局：本轮不为 RTL 镜像 GUI 布局（按钮位置不变），只保证文本内容正确。文本宽度变化导致的溢出在 S8.12 中记录，用 `font.width` 截断或缩放修复。

## 7. 代码规则

- 面向玩家的文本一律 `Component.translatable(key, args...)`。参数中的数字直接传 `Integer`/`Double`，坐标用 `Component.literal(String.valueOf(x))`。
- 日志（`LOGGER`）与异常消息保持英文，不翻译。
- 1.12 的 `LanguageUtility`、`I18n.translateToLocal`（服务端翻译，94 处）全部删除：服务端只发送可翻译组件，由客户端翻译。
- 客户端 `I18n.get(key)` 只能在 client 源集使用。

## 8. 校验脚本 `scripts/check_lang.py`（S2.10 创建骨架，S8.03 完善）

```text
用法：
  python3 scripts/check_lang.py                # 校验，失败退出码 1
  python3 scripts/check_lang.py --dump-en      # 打印合并后的英文全集（JSON）
  python3 scripts/check_lang.py --fix-order    # 按键排序重写所有手写语言文件
  python3 scripts/check_lang.py --report       # 每种语言：总键数、缺失数、多余数、占位符不一致数
检查项：
  1. 每个文件是合法 JSON 对象，值全为字符串，UTF-8 无 BOM
  2. 合并后的 en_us 不含空值
  3. 其他语言的键 ⊆ en_us（多余键 = 错误）
  4. 必需语言（zh_cn fr_fr de_de ja_jp ar_sa）缺失键 = 错误（S8 之前此项只警告，用 --strict 开启）
  5. 占位符集合一致
  6. 不含 '§'
  7. 代码中 Component.translatable("...") 的字面键都存在于 en_us（正则扫描 src/**/*.java）
```

只用 Python 标准库，`python3 -I` 运行。
