## 与步骤卡的差异

- **`EntityType.PIG` → `EntityTypes.PIG`**：26.3 的实体类型常量在 `net.minecraft.world.entity.EntityTypes`（复数），
  `EntityType` 只是类型类；GameTest 用 `EntityTypes.ARMOR_STAND`。
- **`RadarMap` 事件参数**：`onChunkUnload(ServerLevel, LevelChunk)` 直接给 `ServerLevel`（1.12 Forge 事件只给 `Chunk` 再取 world），
  取 `chunk.getPos()` 调 `map.remove(pos)`；`onLevelTick(ServerLevel)` 直接给 `ServerLevel`。
- **入口事件的 `clear`/`clearAll` 命名**：沿用 S1.05 的 `clear(ResourceKey)`/`clearAll()` 风格（步骤卡给 `ServerLevelEvents.UNLOAD`
  写 `RadarRegistry.clear(level.dimension())`），未新增 `onLevelUnload` 别名。
- **`FabricLoader.getInstance().isDevelopmentEnvironment()`** 替 `ICBMClassic.runningAsDev`，与 S1.05 一致。
- **`javax.annotation.Nonnull` 丢弃**：1.12 `RadarMap.add(RadarEntity)` 上有 `@Nonnull`；26.3 源集未引入该注解
  （`grep -rn "javax.annotation" src/main/java` 无结果），注解无运行时行为，故省略并保留原 javadoc 语义。
- **`RadarMap.getRadarObjects` 的 `exact` 短路**：1.12 原式 `exact || exact && cube.isWithin(entity)` 保留未改（见“执行的验证”第 5 项）。

## 未覆盖 / 已知限制

- **`getAllLivingObjectsWithin(Level, x, y, z, distance)` 的高度范围**：按 1.12 常量固定为 `0..ICBMClassic.MAP_HEIGHT(255)`；
  26.3 主世界高度为 `-64..320`，因此 y<0 或 y>255 的雷达目标查不到。步骤卡要求维持 1.12 常量，本步未改（后续如需修正应单独决策）。
- **`RadarMap.getRadarObjects(Cube, exact)` 不做精确立方体裁剪**：因 1.12 的 `exact` 短路写法，结果只是
  chunk 范围（`min>>4-1 .. max>>4+1`）的近似，范围外 1 个 chunk 内的实体会被一并返回。行为照抄，未修旧 bug。
- **`entityFilter` 钩子的默认值**：1.12 只有导弹经 `content/missile/CapabilityMissile` 进入雷达；26.3 入口用
  `ServerEntityEvents.ENTITY_LOAD` 会喂入**所有**实体，故本步默认 `entity -> true`，S4 移植导弹后需改为“仅 `IMissile`”。
  当前状态下所有服务端加载的实体都会被登记到雷达地图（功能上可接受，但列表更大）。
- **`ServerEntityEvents.ENTITY_LOAD` 的实际覆盖范围**：只对“加载进世界的服务端实体”触发。测试范围内实体走
  `addFreshEntity`（覆盖事件挂接），范围外实体不加入世界（避免加载远距离区块）而直接调 `RadarRegistry.add`，
  两者都只依赖注册表行为。未在图形客户端验证；雷达仅服务端逻辑，无客户端代码。
