## 与步骤卡的差异

- 卡片称 `ItemBlockEmpTower` 检查上方空间并放置多个方块；实际 legacy 文件仅扩展 `ItemBlockSubTypes` 并覆盖客户端 tooltip（`legacy-1.12/.../ItemBlockEmpTower.java:16-31`），故只移植真实行为，未增设多方块放置/空间检查。
- 旧物品 metadata 1 由 26.3 的 `DataComponents.BLOCK_STATE` / `type=spin` 表示；metadata 1 tooltip 替换 `%1$s` 为 `ConfigEmpTower.BONUS_RADIUS`，默认状态使用原 `.info` 文案。
- 对 registry-ids.md §1 `TileMulti` 脚注：指定的 `grep -rn TileMulti legacy-1.12/src` 结果仅为 `legacy-1.12/src/main/java/icbm/classic/content/blocks/multiblock/TileMulti.java` 本体和 `legacy-1.12/src/main/java/icbm/classic/content/reg/BlockReg.java:109` 注册，没有 EMP 塔或其它调用者。因此未把 `TileMulti` 合并至 `emp_tower_fake`，保留 `TileEmpTowerFake` 实体。
- `TileEMPTower` 旧类完整源码（`legacy-1.12/.../TileEMPTower.java:55-446`）没有实现 `IEMPReceiver` 或 EMP 命中清空自身缓冲的处理；未凭空新增此行为。
- 旧 block registry id 是 `emptower`，按 registry-ids.md 指定的新 id 注册为 `emp_tower`；fake block id 为 `emp_tower_fake`。`TileEMPTower.REGISTRY_NAME` 保留 Codex 的旧 id `icbmclassic:emptower`。

## 未覆盖 / 已知限制

- 未启动图形客户端实机验证 GUI/rendering；`TESREmpTower.java` 渲染留给 S5.07。
- 无 Tech Reborn Energy、ABM/S7、dispenser 或外部能量互通实现；电池 registry id 仅保留为 `icbmclassic:battery` filter。
- `IEMPReceiver` 行为未实现，原因见“与步骤卡的差异”（legacy 无此行为）。
