### 为什么拆这张卡

S3 全部完成后编译 JAR 部署到 G 盘客户端测试，红物质爆炸一生成实体客户端就崩：

```
19:06:33 [Server thread/INFO] [ICBM-Classic]: TileEntityExplosive: Triggered ... icbmclassic:redmatter ...
19:06:33 [Render thread/ERROR] Render Frame
Caused by: NullPointerException: ... because "renderer" is null
    at EntityRenderDispatcher.shouldRender(EntityRenderDispatcher.java:121)
    at LevelExtractor.isEntityVisible(LevelExtractor.java:313)
```

26.3 `EntityRenderDispatcher#shouldRender` 直接解引用 `renderers.get(entityType)` 的结果，未注册渲染器的实体类型会让**整个渲染线程崩溃**；1.12 的 `RenderManager` 对 null 渲染器只是不画（实体隐形）。模块自 S3.01 起就没有客户端渲染器（步骤卡 `phase-s3-blasts.md:5` 明确「不含渲染器，渲染器在 S4.07」），所以 S3 的构建在客户端「能进游戏、一碰到模组实体就崩」。

用户决定：**只先补齐 S3 已移植的 7 个实体类型的渲染器**（拆分 S4.07），导弹/手雷/炸弹矿车/座椅/降落伞渲染器与粒子仍留在 S4.07 正式步骤。本文件记录这一部分。

## 签名核对（全部用 `javap`/`mcsrc.py` 对 26.3 核实，无凭记忆）

| 依赖面 | 1.12 用法 | 26.3 用法（已核实） |
| --- | --- | --- |
| 渲染器基类 | `Render<T>` + `doRender`/`getEntityTexture` | `EntityRenderer<T, S extends EntityRenderState>`：`createRenderState()`/`extractRenderState(T,S,float)`/`submit(S, PoseStack, SubmitNodeCollector, CameraRenderState)`；`shadowRadius` 取代 `shadowSize` |
| 每帧状态 | 渲染器直接读实体 public 字段 | 每帧 `createRenderState(entity, partialTicks)` 新建状态对象（`EntityRenderDispatcher#extractEntity`），故 1.12 的客户端持久字段仍需留在实体上（`EntityRedmatter#clientVisualSize`、`EntityLightBeam#clientBeamProgress`） |
| 绘制提交 | `Tessellator`/`BufferBuilder` + `GlStateManager` | `OrderedSubmitNodeCollector#submitCustomGeometry(PoseStack, RenderType, (Pose, VertexConsumer) -> …)`；顶点 `addVertex(pose, x,y,z).setColor(...).setUv(...).setLight(...).setOverlay(...).setNormal(...)` |
| 方块模型 | `BlockRendererDispatcher#renderBlockBrightness` | `BlockModelResolver#update(BlockModelRenderState, BlockState, BlockDisplayContext)` + `BlockModelRenderState#submit(...)`；移动方块 `submitMovingBlock(PoseStack, MovingBlockRenderState, int)`；白闪 `TntMinecartRenderer#submitWhiteSolidBlock(..., boolean white, ...)` |
| 贴图 | `bindTexture`/`TextureMap.LOCATION_BLOCKS_TEXTURE` | 由 `RenderType` 携带：`RenderTypes.entityCutout/entitySolid/entityTranslucent(Identifier)`、`beaconBeam(Identifier, boolean)`、`dragonRays()` |
| 渲染类型 | GL 状态机（blend/cull/depth/alphaFunc） | `RenderType` 决定（`RenderPipelines` 按后端编译，GL **或 Vulkan**；本步代码不引用任何后端 API） |
| 图元拓扑 | `begin(7, …)` 四边形 / `begin(6, …)` 三角形列表 | 流水线固定拓扑：`ENTITY_*`/`BEACON_BEAM` = `QUADS`，`DRAGON_RAYS` = `TRIANGLES`（`RenderPipelines` 反编译核实，见「失败与修复」） |
| 注册 | `RenderingRegistry.registerEntityRenderingHandler` | Fabric `EntityRendererRegistry#register(EntityType, EntityRendererProvider)`（`fabric-rendering-v1`；实现把注册缓冲到 map，由 Fabric 在客户端引导时转给原版 `EntityRenderers`） |
| 隐形渲染器 | 空 `doRender` | 原版 `NoopRenderer`（原版自用于 `marker`/`interaction`/`area_effect_cloud`） |
| 视锥剔除 | `getRenderBoundingBox` 无限高 | 覆写 `EntityRenderer#shouldRender(...)` 恒真 |
| 平移 | 渲染器内 `translate(x, y, z)` | 26.3 分发器已把 `PoseStack` 平移到插值后的实体位置，渲染器只做相对偏移 |
| 全亮光照 | `GlStateManager#disableLighting` | 顶点 `setLight(15728880)`（0xF000F0），与 `BeaconRenderer` 一致 |

### 验证边界（必须如实说明）

- 本环境**没有图形栈**：`/usr/lib/x86_64-linux-gnu/dri` 为空、无 swrast/llvmpipe，`runClient` 无法启动（`AGENTS.md` 也把 `runClient` 排除在 Agent 能力之外）。因此**渲染线程不崩的最终证据 = 人工在 G 盘客户端复现红物质/破片/光束**，本步只能保证：编译通过、API 签名经 `javap` 核对、拓扑/图元与流水线一致、无 OpenGL 依赖。
- 外观（颜色/亮度/雾/纹理 wrap）由人工门禁 S5.12 判定；本文件把所有已知视觉差异列在下面。
- 启动自检（`ClientLifecycleEvents.CLIENT_STARTED`）在客户端启动时遍历 `icbmclassic` 命名空间的全部实体类型，逐个用 `EntityRenderDispatcher#getRenderer(EntityRenderState)` 探针查询，缺失时 `LOGGER.error(...)`，成功时 `LOGGER.info("Checked the renderer of N icbmclassic entity types")`——人工启动客户端时请核对这条日志。

## 结果

- 7 个实体类型全部有渲染器；`EXPLOSION_HOLDER`/`SMOKE` 用原版 `NoopRenderer`（与 1.12 空渲染器语义一致）。
- 每个渲染器都只通过 `RenderType` + `SubmitNodeCollector` 提交绘制：**没有任何后端绑定**（无 `RenderSystem`/`GlStateManager`/`GL11`/`RenderPipelines`/`RenderType.create`，只 import 了 `com.mojang.blaze3d.vertex.{PoseStack,VertexConsumer}` 这两个与后端无关的顶点/矩阵抽象），因此 GL 与 Vulkan 后端都适用。
- 1.12 的数值与随机序列**逐字保留**：破片四边形顶点/UV、光柱 UV 动画 `frac(t*0.2 - floor(t*0.1))`、红物质球半径 `max(RENDER_SCALE*size, 0.1)`、外壳脉冲 `ticks%40`、光束 `seed 432L` 的 6 次随机旋转与 `beamCount = (t + t²)/2 * 30`、彩色缓存 `randomColorsForBeams`。

## 与步骤卡的差异 / 有意保留的 1.12 缺陷

1. **铁砧方块损伤**：1.12 `BlockAnvil.DAMAGE = rand.nextInt(2)`（0..1）；26.3 的损伤是方块变体（`Blocks.ANVIL`/`CHIPPED_ANVIL`/`DAMAGED_ANVIL`），按 1.12 语义只随机取前两个，`DAMAGED_ANVIL` 依旧取不到。
2. **铁砧朝向**：1.12 `Direction.Plane.HORIZONTAL.facings()[rand.nextInt(3)]` 取不到第 4 个水平方向，26.3 用 `{NORTH, SOUTH, WEST}` 保持同样行为。
3. **铁砧每帧重随机**：1.12 在 `doRender` 里每帧随机朝向/损伤，26.3 放在每帧一次调用的 `extractRenderState`；1.12 的 `//TODO store rotation and damage in entity to reduce random nature` 原样保留。
4. **引爆方块引信膨胀**：保留 1.12 的 `1 + f³·0.3`（原版 `TntRenderer#getSwellAmount` 是 `f⁴·0.3`）。
5. **白闪**：1.12 第二遍渲染**默认方块状态** + `blend(SRC_ALPHA, DST_ALPHA)` + `polygonOffset(-3,-3)` + alpha `(1-(fuse-partial+1)/100)*0.8`；26.3 用原版 `submitWhiteSolidBlock` 的 overlay 白闪（同一份几何 + `OverlayTexture.pack(u(1),10)`），没有 alpha 渐隐、也没有 `translate(0,0,1)` 的第二遍几何。
6. **光照**：1.12 用 `entity.getBrightness()`（白闪遍 1.0）；26.3 方块模型走 `state.lightCoords`/移动方块的光照引擎，破片/光柱/红物质用全亮顶点光（对应 1.12 的 `disableLighting`）。
7. **`arrowShake` 不同步**：1.12 该字段只在 NBT 里，客户端恒 0，抖动分支实际不生效；26.3 保持同样行为（未新增同步）。
8. **飞行方块不应用实体旋转**：1.12 渲染器忽略 `rotationYaw/Pitch`（只有实体自己转），26.3 同样忽略——已写入证据，避免后续误改。
9. **`failedBlocks` 回退表丢弃**：1.12 用 try/catch 捕获方块渲染异常并回退 `LEAVES`/`STONE`；26.3 的 `submitMovingBlock` 只是把状态入队（`MovingBlockFeatureRenderer` 在延迟阶段解析模型，缺模型时原版给占位模型），没有等价触发点，故不保留占位逻辑。
10. **光柱对齐/混合差异**（1.12 GL 状态 → 26.3 流水线）：
    - 1.12 `alphaFunc(0.1)`、`disableFog`、每次绘制 `glTexParameteri` clamp 贴图：26.3 由 `RenderType`/采样器决定，本步无覆盖点（v 用到 `-1..254`，wrap 模式会影响观感，交 S5.12）。
    - 内层：1.12 是加法混合（`SRC_ALPHA, ONE`）+ 顶点 alpha 0.125 + `depthMask(true)`；26.3 内层用 `beaconBeam(..., false)`（不混合、深度写开），着色器把顶点颜色整体乘进采样色，故内层顶点色改为**全 alpha**（原版 `BeaconRenderer` 同样只对外层用 `ARGB.color(32, color)`），观感从「半透明发光柱」变为「有实心芯的信标光柱」。
    - 外层：与 1.12 一致（`SRC_ALPHA, ONE_MINUS_SRC_ALPHA`、深度写关、alpha 0.125）。
    - 剔除：1.12 `disableCull`，26.3 两条信标流水线 `cull=true`；四边形绕序照 1.12，从外部看一致。
11. **`shouldRender` 恒真**：对应 1.12 无限高的 `getRenderBoundingBox`（光柱不会被视锥剔除）。
12. **红物质几何重写**（1.12 即时模式 → 26.3 提交式）：
    - 球：1.12 `glu` 球体（32×32）；26.3 自建 32×32 球面网格，极点从 Z 轴改到 Y 轴（贴图是纯灰、颜色是纯色填充，朝向无可见影响）。
    - 黑盘：纹理四边形双面绘制（`blackhole.png`，按 `-ticksExisted` 绕 Y 旋转，颜色 (1,0,0,1)）。
    - 光束：1.12 的 `begin(6, POSITION_COLOR)` 三角扇 → `RenderTypes.dragonRays()`（TRIANGLES），按「中心点 + 三个尖端」展开成 3 个三角形；`seed 432L` 的随机序列、六次随机旋转、颜色缓存照抄。
    - 内球用 `entitySolid`（1.12 内球光照未关闭），外壳用 `entityTranslucent`（1.12 外壳 `disableLighting`）。
13. **红物质不再自绘位置**：1.12 在每个子渲染里 `translate(x,y,z)`；26.3 由分发器完成。
14. **`ColorB` 的字节语义**：`ColorB` 组件是**有符号 byte**（1.12 故意保留的写法），1.12 把它们写进归一化的无符号顶点属性；26.3 用 `Byte.toUnsignedInt` 还原同一读法（`RenderRedmatter#toVertexColor`）。
15. **`RedmatterClientLogic` 落点**：1.12 的客户端尺寸插值挂在实体上（`clientLogic` 字段）；26.3 保留为实体上的 `clientVisualSize` + `lerpClientVisualSize(float)`（不引用任何客户端类），渲染器每帧**先拷走上一帧的值再 lerp**，与 1.12「先绘制后 lerp」等价。
16. **`rot`/`mutation` 无方块形态**：26.3 平铺化后这两个爆炸物没有方块（`ExplosiveForms` 注明「registered explosives, they just have no content」），`RenderExBlock` 取不到方块时**不渲染并告警一次**（按 id 去重防刷屏）；1.12 有 `EX_PROP` 方块状态，这是平铺化（ADR 0002）的必然结果。
17. **方块模型放置矩阵**：见下一节的推导与修复。

## 失败与修复

| 现象 / 风险 | 根因 | 处理 |
| --- | --- | --- |
| 红物质光束几何错乱（顶点被跨光束拼接） | 1.12 用 `GL_TRIANGLE_FAN`（5 顶点：中心 + A/B/C + A），26.3 `RenderTypes.dragonRays()` 的流水线是 `PrimitiveTopology.TRIANGLES`（`RenderPipelines` 反编译核实） | 展开为 3 个三角形（中心,A,B / 中心,B,C / 中心,C,A，共 9 顶点），与 1.12 的三角剖分一致；原版 `EnderDragonRenderer#submitRays` 同样每束 9 顶点 |
| 红物质球体几何错乱 | `entitySolid`/`entityTranslucent` 走 `ENTITY_SNIPPET → QUADS`（反编译核实），而实现按单元格写 6 个顶点（两个三角形） | 改为每格 4 顶点（`x00y0 → x10y1 → x11y1 → x01y0`，与注释里的绕序一致） |
| 光柱内层亮度约为 1/8，且不混合 | `beaconBeam(..., false)` = `BEACON_BEAM_OPAQUE`（`ColorTargetState.DEFAULT`＝关闭混合），着色器把顶点颜色（含 alpha）整体乘进采样色 | 内层顶点色改全 alpha，0.125 只用于外层（与原版 `BeaconRenderer` 一致），注释同步修正 |
| 铁砧方块被放到实体西侧一格 | 1.12 的 `translate(y+0.5) + rotate(-90,Y) + translate(-0.5,-0.5,0.5)` 在同一空间里把方块放到实体所在格；搬到 26.3 的移动方块管线后，`rotate(-90)` 把方块整体推开一格（矩阵推导：该序列把 `[0,1]³` 方块映射到 `x∈[实体-1.5, 实体-0.5]`，而原版 `FallingBlockRenderer` 的 `translate(-0.5,0,-0.5)` 映射到 `x∈[实体-0.5, 实体+0.5]`；两者对模型**原点**的平移相同，差别正是那个旋转把模型绕姿态原点转动） | 铁砧分支改用原版 `FallingBlockRenderer` 的放置方式，与 `RenderEntityBlock` 保持同一套映射；`RenderExBlock` 本来就照原版 `TntRenderer`（含收尾的 `rotate(+90)`），无需改动 |
| 客户端崩溃（本步的起因） | 26.3 对未注册渲染器的实体类型在 `shouldRender` 里 NPE；1.12 只是隐形 | 7 个类型全部注册；`IcbmEntityRenderers` 加启动自检，缺失时 `LOGGER.error` |
