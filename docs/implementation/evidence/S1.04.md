## 与步骤卡的差异

1. **`CodexPayload` 增加第三个 record 组件 `type`，并拆成两个 StreamCodec**。步骤卡（与 porting-guide §5）给的是
   `record CodexPayload(Identifier codexId, byte[] body)` + 两个 Type 共用一个 StreamCodec。26.3 编码自定义载荷时写的是
   `payload.type().id()`（上面的字节码证据），而 clientbound/serverbound 的 id 表是分开的；同一个 record 实例无法同时
   报告 `S2C` 与 `C2S`（record 不能有额外实例字段），单实例 + 单 `type()` 会让其中一个方向的 id 写错（服务器收到
   `codex_s2c` 时在 serverbound 表里找不到 codec）。因此实现为
   `record CodexPayload(Identifier codexId, byte[] body, Type<CodexPayload> type)`，两个方向共用同一个 `codec(type)` 私有工厂
   产生 `S2C_CODEC`/`C2S_CODEC`（线上格式一致：`Identifier` + `BYTE_ARRAY`），并提供 `toClient/toServer` 工厂、
   `asClientbound()/asServerbound()` 重标记，由 `IcbmNetwork` 在发送时按方向打标。这是保证双向能真正跑通的必要改动。
2. **`canHandleFromClient` 用 `isAllowServer()`**（步骤卡 §4 写的是 `!codex.isAllowClient()`，§8 又要求 `fromServer()` 的 codex 被拒绝）。
   两者不能同时满足：1.12 的 `fromServer()` = `asClientOnly()`，即 `allowClient=true, allowServer=false`（§8 的括号注释
   「allowClient=false」与 1.12 实现不符）。按 1.12 语义与真实调用点（`GuiLauncherBase` 等对 `.fromClient()` codex 调
   `sendToServer`，服务器侧 `sendToAllAround/sendPacketToGuiUsers` 用 `.fromServer()` codex），服务端可接收的判定是
   `isAllowServer()`；该实现同时满足步骤卡 §8「`fromServer()` codex → 断言 `canHandleFromClient` 为 false」的硬性测试要求。
   客户端接收侧对称使用 `isAllowClient()`。
3. **`decodeAsSetters` / 节点编解码参数类型为 `RegistryFriendlyByteBuf`**（步骤卡写 `FriendlyByteBuf`）。`ItemStack.OPTIONAL_STREAM_CODEC`
   是 `StreamCodec<RegistryFriendlyByteBuf, ItemStack>`，参数若声明为 `FriendlyByteBuf` 则无法直接传给它，而步骤卡 §2
   本身也要求「codex 的 body 编码统一用 `RegistryFriendlyByteBuf`」。`RegistryFriendlyByteBuf extends FriendlyByteBuf`，
   调用方传 FriendlyByteBuf 的兼容性不变。
4. **`encodeBody(TARGET)` 之外多了一个 `encodeBody(TARGET, RegistryAccess)` 重载**：步骤卡只列出 `encodeBody(TARGET)`，
   但注册表相关的节点（`nodeItemStack`）必须有注册表上下文；`encodeBody(TARGET)` 保留为使用 `RegistryAccess.EMPTY` 的便捷入口
   （步骤卡 §8 的 GameTest 用它），发送端用带 `level.registryAccess()` 的重载。
5. **`onFinished` 的玩家类型是 `Player`**（步骤卡写 `ServerPlayer`）。1.12 为 `EntityPlayer`（双端），且 `onFinished` 也会在
   客户端应用 `fromServer()` codex 时回调（此时只有 `LocalPlayer`，没有 `ServerPlayer`，会变成传 null 的陷阱）。
   `fromClient()` codex 的服务器路径仍拿到 `ServerPlayer`（传入实参即 `ServerPlayer`），S5 接线时按需 `instanceof` 收窄。
6. **`sendToTracking(RAW)` 在基类统一实现**：按 `raw instanceof Entity` → `PlayerLookup.tracking(Entity)`，`raw instanceof BlockEntity`
