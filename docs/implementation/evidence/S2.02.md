## 与步骤卡的差异

1. **blast 工厂为占位**：步骤卡要求「逐条照抄 1.12 `newEx(...)` 调用」，但 `BlastTNT`/`BlastNuclear`/… 由 S3.02–S3.09 移植。
   现以 `todoBlast(name)` 占位（调用即抛 `UnsupportedOperationException`），每条 1.12 表达式原样保留在调用上方注释里，
   供 S3 步骤逐字恢复。tier、id、引信时间、内容启用已按 §1 定稿。
   步骤卡提到的 `// TODO(S3.09)` 占位：ender 的两个回调（`todoEnderMissileCoordSet`/`todoEnderBlockCoordSet`）标记为
   `TODO(S3.07)`/`TODO(S3.09)`（ender 爆炸在 S3.07、爆炸物方块在 S3.09）。
2. **数值 ID 层整体删除**：除步骤卡点名的 `forceID`/`getExplosivesIDs()` 外，`ExplosiveRegistry` 的 `id_to_name`/`name_to_id`/
   `nextID`/`loadReg`/`saveReg`/`checkDuplicate`/`lockForce`、`IExplosiveData#getRegistryID()`、`IExplosiveRegistry#getExplosiveData(int)`、
   `IExplosiveContentRegistry#isEnabled(int)`、`IExFuseBlockRegistry` 的 `int explosiveID` 参数一并删除（ADR 0002 无旧存档、无别名）。
   连带迁移调用点：`ICBMClassicHelpers#getExplosive(int, boolean)` 删除；`CapabilityExplosive` 改存 `Identifier`（保存键 `NBTConstants.EXPLOSIVE_ID` 不变）。
3. **内容注册表不再需要 id 缓存**：1.12 的 `ExplosiveContentRegistry` 在 lock 时把名字集映射成 id 集 + `IntHashMap`；
   现直接按名查表，`lockRegistry()` 只冻结名字集与数据缓存。子类不再覆写 `lockRegistry()`（原覆写只做 id 映射）。
4. **`ExplosiveRegistry` 的锁合并为 `lock()`**：1.12 分 `lockNewExplosives()`+`completeLock()`；步骤卡要求 `lock()`，故合并
   （锁新爆炸物 + 锁各内容注册表）。
5. **`ExplosiveData` 不再用 Lombok**：显式实现 `getRegistryKey/getTier/compareTo/equals/hashCode/toString`；
   `compareTo` 由数值 id 改为按 registry key 字符串（1.12 的顺序意义来自 id，已由 `ExplosiveForms.ORDER` 承担）。
6. 修掉两处失效的 TODO 步骤标记（在我已编辑的 `ICBMClassicAPI` 内）：`PROJECTILE_DATA_REGISTRY` → S3.01、
   `EXPLOSIVE_CUSTOMIZATION_REGISTRY` → S3.07；`CapabilityExplosiveStack`/`ICBMClassicHelpers#getExplosive(ItemStack)` 的 S2.02 标记 → S2.05
   （需要在 S2.05 注册平铺化物品后才能实现）。
