# S6.08 人工门禁：Tech Reborn 实机验收材料

> 状态：`[H]` 人工门禁（实机交互需人类在装有 Tech Reborn 的环境中确认；本步骤仅准备验收材料并验证自动构建）。

## 目标
在装有 **Tech Reborn**（其依赖 `team_reborn_energy` 5.0.0）的运行环境下，验证 ICBM-Classic 机器与 TR 能源生态互通：供能、受电（只读）、电池充放电、EMP 抽空、GUI 显示。所有对外能量交互统一经由 `icbm.classic.lib.energy`（S6.01–S6.07），`team.reborn.energy.*` 仅在该包内 import。

## 验收前提
- 将 Tech Reborn 加入运行依赖（其传递依赖 `teamreborn:energy:5.0.0`，与 S6.01 内嵌版本一致）。
- Loader 在存在多个 `team_reborn_energy` 时选择**较高版本**属正常（S6.01 `energy-fe.md §5.1` 已记录），不应视为冲突。
- 构建产物已内嵌能源库：`META-INF/jars/energy-5.0.0.jar`（S6.01 验证，`unzip -l build/libs/ICBM-classic-*.jar | grep energy-5.0.0.jar`）。

## 验收清单（人类实机逐项确认）
- [H] **供电**：TR 能源机 / 电缆向 ICBM 机器（发射台基 `launcher_base`、巡航发射器 `cruise_launcher`、发射台屏幕 `launcher_screen`、雷达站 `radar_station`、EMP 塔 `emp_tower`）注入 FE，机器存量上升，`IcbmEnergyBuffer` 增长，GUI 能量条增长。
- [H] **受电只读**：外部无法从机器抽取能量（`ExposedEnergyStorage.extract` 返回 0，S6.02）；多台发射台经 `launcher_frame`/`launcher_connector` 组成的网络按均分注入（S6.03）。
- [H] **电池物品**：TR 充电器 / 放电器对 `icbmclassic:battery`（`BatteryItem`，容量 1,000,000 FE，最大输入 10,000 FE，最大输出 1,000,000 FE，S6.04）正常充放电；将满电电池放入机器电池槽后，机器 `tickPower()` 在 `ConfigMain.REQUIRES_POWER=true` 时从电池取能（S6.04）。
- [H] **EMP 抽空**：EMP 塔激活时抽空范围内 TR 机器 / 电池能量，受 `ConfigMain.EMP_DRAIN`（默认 10,000 FE/方块）限制，能量进虚空（S6.05）；`REQUIRES_POWER=false` 时 EMP 仍按原逻辑工作。
- [H] **无版本冲突**：客户端日志无 `team_reborn_energy` 重复 / 冲突报错；Loader 选较高版本正常加载。
- [H] **GUI**：机器界面能量条与悬停提示（存量 / 容量，FE 经 `EnergyFormat` 格式化如 `1.2k FE`）正常显示并随充能实时更新（S6.06）。

## 自动化验证（本步骤已执行）
- `export JAVA_HOME=/usr/lib/jvm/java-25-openjdk && ./gradlew build` → `BUILD SUCCESSFUL`，153 个 GameTest 全部通过（含 S6.02 `EnergyTransactionGameTest`、S6.03 `LauncherNetworkEnergyGameTest`、S6.04 `BatteryDischargeGameTest`、S6.05 `EmpDrainGameTest`、S6.07 `EnergyInteropGameTest`）。
- 构建前已修复 GameTest 跨测试共享状态污染（`4f5ace12d`，`defaultMatchers` 泄漏 + 雷达夹具确定性），测试套件连续 10 次 `runGameTest` 全绿，具备稳定验收基线。
