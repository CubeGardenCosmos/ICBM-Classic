## 结果

步骤卡的“操作”1–6 与“目标”逐条对应：

1. `EntityProjectile` 干系继承 `net.minecraft.world.entity.Entity`（未继承原版 `Projectile`，未 BLOCKED）：满足。
2. 移动/碰撞检测改用 `level.clip(new ClipContext(from, to, Block.COLLIDER, Fluid.NONE, this))` 与
   `ProjectileUtil.getEntityHitResult(level, this, from, to, aabb, predicate, 0.3F)`：满足（签名已核对并粘贴）。
3. `IEntityAdditionalSpawnData` 删除；`writeSpawnData` 同步的唯一字段 `freezeMotion` 改为
   `SynchedEntityData`（`EntityProjectile.FREEZE_MOTION` + `isFreezeMotion()/setFreezeMotion()`）：满足。
4. `lib/projectile/vanilla/**` 五个原版投射物数据类全部移植，`registerVanillaDefaults()` 注册
   `minecraft:item`/`minecraft:entity`/`arrow.normal`/`arrow.spectral`/`arrow.tipped` 与箭、光灵箭、药箭、
   雪球、鸡蛋、全部生成蛋的堆栈转换：满足。
5. `defineSynchedData(SynchedEntityData.Builder)` 定义默认值；存档走 `SaveHandler`
   （`mainRoot().nodeSavable("ground", …, InGroundData::new)` + `addRoot("ticks")` 的 air/ground）：满足。
6. GameTest：`TestProjectile`（`icbmclassic-test:test_projectile`，由测试模组的 `main` 入口
   `icbm.classic.test.TestModInitializer` 在 mod 初始化期注册）以固定速度撞石墙，断言
   `onImpact` 触发（`TestProjectile#impacted`）且实体被移除；另加一条基类存档往返（ticks 与
   卡住的方块 pos/state）：满足。

“目标：`EntityProjectile<E>` 基类可被导弹、飞行方块、子弹药、降落伞、气球继承”满足：基类已是可直接继承的
非抽象数据骨架（唯二抽象成员是 26.3 `Entity` 要求子类实现的 `hurtServer`），GameTest 已用最小子类继承并运行。

## 与步骤卡的差异

- **继承链**：1.12 `EntityProjectile extends EntityICBM`，`EntityICBM` 属 S5.01。按步骤卡改为直系继承 `Entity`，
  并把 `EntityProjectile` 自己用到的 `EntityICBM` 成员内联：`hasHealth`（`canBeDestroyed` 用，`EntityMissile`
  在 S4.01 会置 true）。`getVelocity()`/`getPredictedPosition()` 在 1.12 的投射物代码里没有调用点，留给 S5.01。
- **伤害源**：1.12 `public static final DamageSource DAMAGE_SOURCE = new DamageSource("icbmclassic:projectile")`
  在 26.3 无法静态构造（伤害源来自数据包 `damage_type`）。`getImpactDamageSource` 暂返回 null 并留
  `TODO(S3.02)`（1.12 本来就有 null 分支：跳过伤害但仍执行 `onImpact`）。
- **同步字段**：`freezeMotion` 是 1.12 唯一经 `writeSpawnData` 发给客户端的字段，故只有它改 SynchedEntityData；
  `sourceOfProjectile`（`Pos`）、`shootingEntityUUID`、`ticksInAir` 在 1.12 未同步给客户端，且 26.3 没有
  `Pos`/`UUID` 的原版序列化器，保持普通字段。
- **方法改名**：`getGravity()` 在 26.3 是 `final`（Entity 改为按属性算重力）→ 投射物常量改用
  `getProjectileGravity()`；`canTriggerWalking()`、`getMaxInPortalTime()` 在 26.3 无对应钩子 → 删除；
  `isInRangeToRenderDist` → `shouldRenderAtSqrDistance`（`getRenderDistanceWeight()` 的等价物是静态
  `Entity.getViewScale()`，`getRenderBoundingBox().getAverageEdgeLength()` → `getBoundingBox().getSize()`）。
- **客户端插值**：1.12 覆写 `setPositionAndRotationDirect` 直接吸附；26.3 只有实体自建
  `InterpolationHandler` 才插值，默认 `NO_OP` 就是吸附 → 不需要覆写。
- **射线细节**：1.12 手写实体循环里的“命中盒 +0.3F”“取最近”“射手 5 tick 内不自撞”分别落到
  `getEntityHitResult(..., 0.3F)` 与谓词 `shouldCollideWithEntityTrace`；`rayHit.typeOfHit != MISS` 的判断
  改为 `rayHit.getType() != HitResult.Type.MISS`（26.3 的 `clip` 未命中时返回 MISS 结果而不是 null）。
  该差异里 `ClipContext.Block.COLLIDER` 不含传送门方块（1.12 的 rayTraceBlocks 会命中传送门），但
  1.12 对传送门注册的反应正是 CONTINUE_NO_IMPACT（无撞击、保持飞行），净行为一致。
- **方块接触回调**：`state.getBlock().onEntityCollidedWithBlock(...)` → `state.entityInside(level, pos, this,
  InsideBlockEffectApplier.NOOP, false)`；`updateMotion()` 的 `doBlockCollisions()` → `applyEffectsFromBlocks(from, to)`。
- **`shouldCollideWith`**：1.12 排除 `icbm.content.entity.EntityPlayerSeat`（属 S4.06），本步无法引用该类，留
  `TODO(S4.06)`；保留等价判据 `entity.isPickable()`（1.12 `canBeCollidedWith()`）。
- **`InGroundData.getMaterial()` 删除**（26.3 无 Material，porting-guide §2.1），调用点改判 `state.isAir()`。
- **`ProjectileStack`**：`IProjectileStack<EntityParachute>` 的类型参数（EntityParachute 属 S4.06）暂放为 `Entity`。
- **`CapabilityProjectileStack` DROPPED**：26.3 无 Capability（porting-guide §2.6），物品直接暴露投射物数据；
  `ProjectileDataRegistry.find` 中对应的 capability 查询留 `TODO(S4.06)`。
- **生成蛋**：1.12 用单一 `Items.SPAWN_EGG` + metadata（`ItemMonsterPlacer.getNamedIdFrom`）；26.3 是“每个实体一个
  生成蛋物品”，故 `registerVanillaDefaults` 遍历 `BuiltInRegistries.ITEM` 中所有 `SpawnEggItem` 注册同一转换，
  实体 id 走 `SpawnEggItem.getType` + `EntityType.getKey`，EntityTag 走 `DataComponents.ENTITY_DATA` +
  `TypedEntityData#copyTagWithoutId`。
- **保留的 1.12 缺陷（未修）**：`CachedProjectileData.apply` 的判空写反（`if (instance != null)` → 永不缓存、
  恒返回 null）、`moveTowards` 的 `vecY` 用 `deltaX` 计算、`SpectralArrowProjectileData` 在 1.12 实际
  `new EntityTippedArrow`（本步按 NAME 语义改用 26.3 的 `SpectralArrow`，已在文件与账本注明）。按 porting-guide §1.2
  “行为等价优先、不修旧 TODO/缺陷”，除 `SpectralArrow` 外全部照旧。
- **`ProjectileBlockInteraction`**：Material 表 → 方块标签表（`BlockTags.LEAVES`/`SNOW`/`IMPERMEABLE`，即 1.12
  文件自己 TODO 指向的标签方案）；`Blocks.PORTAL` 在 26.3 不存在 → `Blocks.NETHER_PORTAL`；末地传送门从
  `TileEntityEndGateway#teleportEntity` 改为委托 `state.entityInside(...)` 后返回 `TELEPORTED`；
  `breakBlock` 去掉 Forge 专用的 `canEntityDestroy` 守卫（默认恒 true）。
- **接线位置**：1.12 在 `ICBMClassic#preInit/postInit` 内联；本步同样写在 `ICBMClassic#onInitialize`
  （`ProjectileBlockInteraction.register()` + 建注册表并赋给 `ICBMClassicAPI.PROJECTILE_DATA_REGISTRY`）。
  区别：`registerVanillaDefaults` + 注册事件 + `lock()` 推迟到首次 `ServerLifecycleEvents.SERVER_STARTING`
  （原因见下节失败 2，等价于 1.12 的 postInit）。
- **文档一致性**（AGENTS.md 要求同改动修正）：`ModEntities` 注释由 “S3.01/S3.03” 改为 “S3.03”（本步没有新增
  实体类型）；`ICBMClassicAPI` 中 `PROJECTILE_DATA_REGISTRY` 的 `TODO(S3.01)` 改为接线说明。

## 失败与修复

1. `compileJava` 首轮 5 个 error：
   - `IProjectileData<?>` 传给 `<E extends Entity> spawnProjectile(IProjectileData<E>, …, Consumer<E>)` 推断失败
     → `find` 改回 1.12 的 raw `IProjectileData` 返回类型（注册表只读接口本来就按 raw 设计）。
   - `super.defineSynchedData/readAdditionalSaveData/addAdditionalSaveData` 不可直接调用（26.3 `Entity` 里是
     abstract）→ 删除 super 调用（Entity 自身基础字段由 `saveWithoutId`/`load` 处理）。
   - `getGravity()` 在 26.3 `Entity` 是 final → 改名 `getProjectileGravity()`。
2. `runGameTest` 首轮 `java.lang.NullPointerException: Components not bound yet`
   （`ProjectileDataRegistry.registerVanillaDefaults(ProjectileDataRegistry.java:56)`，即 `new ItemStack(Items.ARROW)`）：
   26.1 起 `ItemStack` 不能在 mod 初始化阶段创建（ModItems/blocks 都只在延迟 lambda 里建栈）。
   修法：注册表实例仍在 onInitialize 创建（内容步骤可在 lock 前注册自己的转换），而 vanilla 默认项、注册事件与
   `lock()` 放到首次 `SERVER_STARTING`——与 1.12 把这三件事放在 postInit 的顺序一致。
3. `projectile_survives_save_round_trip` 首轮失败：断言拿相对坐标与存档里的绝对坐标比较，
   改为 `helper.absolutePos(groundPos)` 后通过（存档内容本身正确，从失败信息里的 NBT 可见
   `ground:{pos:[I;…],side:"up",state:"minecraft:stone"},ticks:{air:1234,ground:4321}}`）。

## 未覆盖 / 已知限制

- 渲染相关行为（`shouldRenderAtSqrDistance` 距离、客户端插值）只在编译层面验证，未在图形客户端实测（无渲染器，
  S4.07 才做，且属人工门禁）。
- 实体/方块射线只在 GameTest 的“直线撞 4x4 石墙”场景验证；斜射、擦边、连续命中未覆盖。
- `ProjectileDataRegistry.find` 缺 capability/IProjectileStack 分支（S4.06 接入），当前所有未登记物品都退化为
  `ItemProjectileData`。
- `ProjectileBlockInteraction` 的标签匹配对同时命中多个标签的方块以 HashMap 迭代顺序为准（1.12 一个方块只有
  一个 Material，不存在该情形）。
- 基类的存档往返只覆盖 `ground`/`ticks` 两个节点（`source` 节点在 1.12 就是注释掉的）。
