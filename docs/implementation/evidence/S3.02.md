## 步骤卡第 1 步的结论（Explosion 继承决策）

26.3 的 `net.minecraft.world.level.Explosion` **是接口**（唯一原版实现 `ServerExplosion`），因此按步骤卡规则：
`Blast` 不再继承而是 `implements IBlastInit, IBlastRestore, Explosion`，1.12 从 `Explosion` 父类继承的字段（`world/x/y/z/size/exploder`）改在本类声明；
`doExplosionA()`/`doExplosionB(boolean)`（1.12 里只为屏蔽原版爆炸路径而重写）、`super(null,null,0,0,0,0,false,false)` 构造调用、`ForgeEventFactory.onExplosionStart` 取消钩子全部删除；legacy 中并不存在 `ExplosionEvent` 用法（已 grep 确认），无需处理。
查询方法映射：`center()`→`getPosition()`、`radius()`→`getBlastRadius()`、`getDirectSourceEntity()`→`exploder`、`getIndirectSourceEntity()`→`Explosion.getIndirectSourceEntity(exploder)`（原版静态工具，与 1.12 `Explosion#getExplosivePlacedBy` 等价）、`getBlockInteraction()`→`DESTROY`、`canTriggerBlocks()`/`shouldAffectBlocklikeEntities()`→`false`、`level()`→模式匹配 `world` 得到 `ServerLevel`，否则抛 `IllegalStateException`（ICBM 爆炸只在服务端运行，不静默回退原版行为）。

## 与步骤卡的差异

- 步骤卡步骤 2 要求“`MinecraftForge.EVENT_BUS.post(new BlastEvent…)` → `api/events` 中的 Fabric Event”：legacy `Blast` 只 post `BlastBuildEvent`，已改为 `BlastBuildEvent.EVENT.invoker().onBlastBuilt(new BlastBuildEvent(this))`；legacy 无其它 blast 事件触发点。
- 线程相关成员（`thread`、`threadResults`、`threadComplete`、`createAndStartThread`、`getThread`、`markThreadCompleted`、`isThreadCompleted`、`addThreadResult`、`getThreadResults`）本步**删除**（步骤卡 S3.06 要求在 `LevelSnapshot`/`BlockEditQueue` 上重建）；账本中 3 行 `content/blast/thread/*` 的步骤由 S3.02 改标为 S3.06。
- `doDamageEntities` 的方块遮挡用 `ServerExplosion.getSeenPercent(Vec3, Entity)`（1.12 `World#getBlockDensity` 的 26.3 对应实现），伤害调用改 `hurtServer(serverLevel, …)`，非 `ServerLevel` 时按 1.12 “客户端不做伤害”的语义跳过。
- `EntityExplosion` 不再实现 `IEntityAdditionalSpawnData`（26.3 无此接口）：爆炸 id 与 Y 偏移进 `SynchedEntityData`，**客户端不再构造 blast 实例**（1.12 会在 `readSpawnData` 里构造，实际只用于空的 `clientRunBlast()` 钩子）；`ticksExisted`→`tickCount`、`setDead()`→`discard()`、`getName()` 返回 `Component.literal`（1.12 的调试字符串 "Explosion[…]"，非玩家文案，不进语言文件）。
- 26.3 无 `preventEntitySpawning`/`ignoreFrustumCheck`/`canTriggerWalking` 对应物：前两者分别由数据驱动生成与渲染器 `shouldRender` 负责（S4.07），第三者在该版本不存在，均已删除并在代码注释中说明。
- `Mth.sqrt(float)` 替代 1.12 `MathHelper.sqrt(double)`（沿用 S3.01 既有写法）；`EntityExplosion` 用 `setPosRaw` 而非 `setPos`，避免每 tick 重复应用包围盒中心偏移（1.12 只写 `posX/Y/Z`）。
- `ModEntities.EXPLOSION_HOLDER` 为 `static`（非 `final`），因为注册发生在 `register()` 内，无法给空白 final 赋值；沿用仓库既有约定。

## 保留的 1.12 缺陷（行为等价优先，未修）

1. `Blast#getBlastSource()` 自递归（1.12 `Blast.java:470-473` 即 `return getBlastSource();`），26.3 版逐字保留，附注释说明；仅 `BlastEvent#getSourceEntity()` 会触发它，1.12 同样如此（会抛 `StackOverflowError`，子任务用一次性 JVM 冒烟测试确认该行为已被保留）。
2. `imp/BlastBase#getBlastRadius()` 返回 `(float) Math.min(blastSize, 1)`（1.12 疑似写反），逐字保留。
