## 与步骤卡的差异

1. **`sounds.json` 条目不再写 `category`**：26.3 的 `SoundEventRegistration` 只有 `sounds`/`replace`/`subtitle`（javap 见上），
   分类由播放点的 `SoundSource` 决定；1.12 的分类记在 `ModSounds` 注释里。
2. **删掉了 1.12 每个条目的 `"sream": false`**：1.12 的拼写错误（应为 `stream`），26.3 单文件键名以 `name`+可选
   `stream` 为准，默认 `stream=false` 等价，删除后不改变播放行为。
3. **`sounds[]` 改为字符串数组**：与 `{"name": ..., "sream": false}` 等价（Gson 反序列化同一 `Sound` 记录），更短且无冗余键。
4. **`sounds.json` 键名与 `.ogg` 文件名解耦**：事件 ID 按步骤卡转 snake_case（`missileinair` → `missile_engine` 等 5 处），
   但 `.ogg` 保持 1.12 原名（`missileinair_short.ogg`），避免改资源文件名（`.ogg` 改名不在步骤卡范围内）。
5. **`RegHelper.sound(String)` 而不是在 `ModSounds` 里直接 `Registry.register`**：与本仓库其它 `Mod*` 类一致（统一走 `RegHelper`）。
6. **`en_us.json` 本步只含 16 个字幕键**：S2.10 用 `migrate_lang.py` 把 1.12 的全部文本迁进来（字幕值随之变成 1.12 原文），
   并由 `mergeLang` 与 datagen 生成的名称合并；本步的文件只是过渡状态。

## 顺带修复（S2.03 的 `SimpleBlocksGameTest` 不稳定，不是本步功能改动）

- 现象：`simple_blocks_game_test_..._spikes_hurt` 间歇失败（`zombie should be hurt by the spikes, health is 20.0`），
  同一次改动前后时通时不通（本步内 5 次运行中 3 次失败、2 次通过）。
- 定位（临时打印 `isRemoved()`/`getRemovalReason()`/chunk 状态）：实体**在生成后 1 tick 内被 `DISCARDED`**；
  `difficulty=NORMAL`、`chunkTicking=true`、`hasChunk=true`、`addFreshEntity=true`，位置在测试包围盒内（8×8×8）。
  即 26.3 `Mob.checkDespawn()` 的「附近没有玩家 → 按随机概率移除」分支（`getNearestPlayer(this, -1)` 命中远处玩家、
  距离超过 despawn 距离后进入随机 roll）在本测试里生效；roll 是随机的，因此时通时不通。
- 修复：`zombie.setPersistenceRequired()`（标准做法，等价于 1.12 的 `enablePersistence()`），
  失败信息补上僵尸坐标与所在方块便于以后定位。修复后连跑 3 次全绿。
- 未改动方块/伤害逻辑，仅测试稳定性；S2.03 的结论（尖刺对生物造成伤害）不变。

## 未覆盖 / 已知限制

- **声音的实际播放**（音量/音高/远距离延迟、随机多文件选择）要客户端实机听，属人工门禁（S5.12）；本步只验证注册、
  字幕键与文件可解析。
- `SoundSource` 分类尚未落到任何播放点：播放点（爆炸、导弹、机器）分别在 S3/S4/S5 移植，届时按 `ModSounds` 注释取值。
- 客户端 `runClient` 只能验证 `sounds.json` 被解析、资源包包含本模组资源；OGG 只有在首次播放时才由 `SoundEngine`
  解码，启动日志无法覆盖解码失败，故补了 `OggS` 头校验。
- 1.12 的 `ICBMSounds.play(...)` 便捷方法未移植；若 S3/S4 出现大量重复的播放代码，再评估是否需要统一的播放门面。
