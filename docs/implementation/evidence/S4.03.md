## 改动清单

### 新增文件

- `src/main/java/icbm/classic/content/missile/tracker/MissileTrackerData.java`：导弹模拟数据记录。
  - 使用 Mojang `RecordCodecBuilder` 创建编解码器；保留 1.12 的 NBT 键语义（`ticks`、`target`、`data` 与可选 `preLoadChunkTimer`）。
  - `TARGET_POS_CODEC` 支持 1.12 的 `{x, y, z}` CompoundTag 格式与 26.3 的 `[x, y, z]` 列表格式双向解码。
  - 导弹实体数据使用 `TagValueOutput` 与 `missile.saveWithoutId` 生成，显式移除 `Pos` 与 `Motion` 键并注入 id `icbmclassic:explosive_missile`。
- `src/main/java/icbm/classic/content/missile/tracker/MissileTrackerWorld.java`：继承 `SavedData`。
  - 持有 `missileList`（飞行数据模拟队列）、`missileSpawnList`（到达目标后的就绪队列）、`trackedChunks`（已强加载区块及其剩余倒计时）。
  - 每 20 tick（1秒）运行一次更新（`ticks++ >= 20` 门控 `runSimulationTick`）。
  - 到达目标（`ticksLeftToTarget <= 0`）后使用 26.3 原版 `ServerLevel#setChunkForced(int, int, boolean)` 强加载目标区块与 4 邻共 5 个区块（冷却 60 秒，预加载倒计时 5 秒），触发 `MissileChunkEvent.Load` 并回读可变 `timeLeft`。
  - 强加载区块倒计时到期时触发 `MissileChunkEvent.Unload`，若未被监听器取消则调用 `setChunkForced(..., false)` 卸载。
  - 预加载倒计时到期时，通过 `TagValueInput` 恢复实体，以 `ConfigMissile.SIMULATION_ENTER_HEIGHT` 与 `SIMULATION_ENTER_SPEED` 注入位置与垂直速度，以 `DeadFlightLogic(100)` 垫底，调用 `launch()` 并通过 `ServerLevel#addFreshEntity` 放回世界。
- `src/main/java/icbm/classic/content/missile/tracker/MissileTrackerHandler.java`：静态门禁与生命周期调度入口。
  - `simulateMissile(EntityExplosiveMissile)` 检查实体存活、非乘骑状态，触发 Fabric `MissileEvent.EnteringSimQueue`（尊重回调取消），成功后调用 `missile.discard()` 移除并加入 SavedData。
  - 维护 `ConcurrentHashMap<ResourceKey<Level>, MissileTrackerWorld>` 缓存，提供 `onLevelLoad`、`onLevelUnload`、`onLevelTick`、`clearAll`。
- `src/gametest/java/icbm/classic/test/missile/MissileTrackerGameTest.java`：3 个用例覆盖模拟移交、实体移除、目标上空生成与 Codec 往返。

## 关键技术决策

1. **`SavedDataType` 与 `DataFixTypes` 传参**：
   - 经 `javap -c net.minecraft.world.level.storage.SavedDataStorage` 字节码分析，`readTagFromDisk` 第 109–119 行直接对传入的 `DataFixTypes` 调用 `dataFixType.update(...)`，若为 `null` 将在从磁盘读取 SavedData 时触发 `NullPointerException`：
     ```
     109: aload_2
     ...
     119: invokevirtual net/minecraft/util/datafix/DataFixTypes.update:(Lcom/mojang/datafixers/DataFixer;Lnet/minecraft/nbt/CompoundTag;II)Lnet/minecraft/nbt/CompoundTag;
     ```
   - 因此遵循步骤卡说明，使用无害的安全枚举值 `DataFixTypes.SAVED_DATA_COMMAND_STORAGE`。
2. **区块外强加载机制**：
   - 1.12 使用已废弃的 Forge ChunkManager Ticket；26.3 直接使用原版 `ServerLevel#setChunkForced(int chunkX, int chunkZ, boolean add)`（javap 核对入参为 `(int, int, boolean)`）。
   - 强加载目标区块及 4 邻（共 5 区块），触发 `MissileChunkEvent.Load`；超时卸载时触发 `MissileChunkEvent.Unload`，均回读可变的 `timeLeft`。
3. **实体存取与重构**：
   - 存档采用 `missile.saveWithoutId(TagValueOutput)` 产出 `CompoundTag`，剔除 `Pos`/`Motion` 坐标以支持远距离目标重定位；
   - 恢复时使用 `new EntityExplosiveMissile(...)` 配合 `missile.load(TagValueInput)`，随后通过 `missile.snapTo(...)` 将实体投放到目标坐标上空的 `ConfigMissile.SIMULATION_ENTER_HEIGHT` 高度并设定向下速度，确保与 1.12 表现一致。

## 与步骤卡的差异

- 步骤卡草案提示 `MissileTrackerData extends SavedData`，但 1.12 实际设计中 `MissileTrackerWorld` 是持有列表的 SavedData，`MissileTrackerData` 为单条记录。本步按操作指令将 `MissileTrackerWorld` 改为 `extends SavedData`，`MissileTrackerData` 为包含 RecordCodec 的数据类，结构更加清晰且保留 legacy 语义。
- `SavedDataType` 的 `DataFixTypes` 传 `null` 会在反序列化时抛出 NPE，已按提示使用 `DataFixTypes.SAVED_DATA_COMMAND_STORAGE`。
- `LoadedChunkPair` 标为 DROPPED，因为 `MissileChunkEvent` 与内部 `TrackedChunk` 已直接携带 `ChunkPos` 与 `timeLeft`。

## 未覆盖 / 已知限制

- GameTest 运行在平坦/虚空结构的测试关卡中，强加载区块的实际持续卸载与持久化机制由单元/集成测试与 Minecraft 原版 `setChunkForced` 机制保证，未在图形客户端多世界跨维度实机运行。
