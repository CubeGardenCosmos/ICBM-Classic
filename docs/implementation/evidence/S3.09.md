## 结果

- 23 个爆炸物方块全部可点燃（红石、火焰/熔岩相邻、打火石/火焰弹、燃烧箭、被爆炸连锁），点燃即移除方块并生成 `primed_explosive`（引信由实体首 tick 从 `ICBMClassicAPI.EX_BLOCK_REGISTRY.getFuseTime` 取，与 1.12 相同）。
- 放置时把物品的 `icbmclassic:explosive_settings` 组件复制进方块实体，破坏（pick-block）时再带回物品；自定义数据现在能存档往返（见「差异 D」）。
- 末影爆炸物的激活监听器（1.12 的死代码）现在可用：手持 GPS 数据物品激活 → 写入末影目标坐标并提示。

## 与步骤卡的差异

- **A. 被爆炸引爆的钩子**：卡片建议核对 `wasExploded`；26.3 实际可用的是 `BlockBehaviour#onExplosionHit`（1.12 `onBlockExploded` 的对应物），理由见「签名核对」。`wasExploded` 在 26.3 无调用方且在方块移除后执行，会拿不到持有 1.12 capability 的方块实体。
- **B. 引信语义与 1.12 一致**：`hasBeenTriggered` 公开、置位后不复位、不存档；方块不设置引信（1.12 也不设置），1.12 的 `//TODO check for tick rate` 原样保留。
- **C. 有意把 1.12 死代码接活**（卡片 + 用户范围要求）：激活监听器（1.12 只写 map、`BlockActivateFunction#onActivate` 无调用方）现在由 `useWithoutItem` 调用并传 `InteractionHand.MAIN_HAND`（`useWithoutItem` 无 hand 参数）。另外：26.3 组件只有一个 `ender_target` 字段，故末影 setter 是**替换**而非 1.12 的追加自定义。
- **C3. 设置未接入爆炸行为**：1.12 从未在任何地方调用 `IExplosive#applyCustomizations`，故本步也不把存下的末影目标应用到爆炸；`Settings → IExplosiveCustomization → blast` 的接线属 S4.06 设置管线（`CapabilityExplosiveStack` 的 `TODO(S2.05)` 是标记）。
- **D. 有意修复的 1.12 缺陷**：自定义数据现在能存档往返（1.12 只写物品栈，`CapabilityExplosiveStack#toStack` 留有 "TODO save customizations"，末影目标会丢）。步骤卡要求「组件/item → 放置 → 存档」往返，故保留 1.12 键名 `explosive_stack`、值改为设置复合。
- **E. 保留的 1.12 缺陷/怪癖**：两个 trigger TODO、放置时的 "TODO turn into event and logger" 日志（双侧照 1.12）、breaching 方向特例（`getDirection().getOpposite()`，即 1.12 TODO 的成因）、`hasBeenTriggered` 不清不存、1.12「未知爆炸物 id 回退到 0」分支在平铺化后不可能存在（无对应物）。
- **F. 发射器**：本步没有把任何东西推迟到 S5.09。1.12 只为手雷/炸弹矿车注册了 dispense 行为，爆炸物方块依赖原版默认行为，两侧一致。
- **G. 其它**：`Blocks.FLOWING_LAVA` 在 26.3 不存在（流动熔岩是 `Blocks.LAVA` 的流体状态），故 1.12 的 `FIRE/FLOWING_LAVA/LAVA` 三元判断收敛为二元；未用 `Properties#ignitedByLava()`（那会让熔岩消耗方块，1.12 不是这行为，火焰/熔岩由 `setPlacedBy` 处理）；挖掘掉落仍是普通方块物品（loot table，S2.07），仅 pick-block 带回设置组件。
- **H. 新增两条英文文本**：见上「改动文件」；`check_lang.py` 要求它们存在。
