## 与步骤卡的差异

1. **线程化爆炸的落地方式**：步骤卡要求“线程化爆炸用 `succeedWhen`”，并要求 `thread/**` 在 S1.09 框架上重写。实际做法：
   - 新增 `content/blast/threaded/BlastThreaded`（1.12 里散在 `Blast` 的线程字段与其 `ThreadExplosion` 外壳在 26.3 的归处）：服务端抓 `LevelSnapshot` → 工作线程只读快照收集坐标 → 回主线程经 `BlockEditQueue` 按预算 `destroyBlock`（`BlockState#onExplosionHit`，等价 1.12 `onBlockExploded` + 掉落 + `wasExploded`）。
   - `BlastSonic`、`BlastAntiGravitational`、`BlastRadioactiveBlockSwaps` 改为继承 `BlastThreaded`；`BlastBeam` 因为有**两趟** worker 且两趟都**不销毁**收集到的方块（第一趟挑飞行方块、第二趟挑要变形的方块），仍继承 `Blast` 并直接用 S1.09 框架（每次 `capture` 独立快照、完成回调 `server.execute` 回主线程），保留了 1.12 的 8 个 `has*` 标志与 100 tick 的 `secondThreadTimer` 时序。理由是 `BlastThreaded` 的完成路径会销毁并结束爆炸，与光束语义冲突。
2. **1.12 的旧线程类不复活**：`ThreadExplosion`/`ThreadLargeExplosion`/`ThreadSmallExplosion` 的收集逻辑（射线步进、阻力回调）被搬进各 `doRun(int, Consumer<BlockPos>)`；账本里这 3 行的步骤此前已由 S3.02 改标为 S3.06，本步的 `BlastThreaded` 只承担基类职责，具体线程化爆炸（nuclear/thermobaric/antimatter）仍在 S3.06。
3. **`rot` 的替换表**：按步骤卡要求先用 `BuiltInRegistries.BLOCK` 按 id 解析 `radioactive_dirt`/`radioactive_stone`（不存在则跳过并 warn），并留 `// TODO(S3.08)` 指向 `RadioactiveHandler`；S3.08 需替换该表并补 rot 的断言。
4. **爆炸物方块连锁**：`BlastTNT`/`BlastSonic` 里 1.12 的 `block == BlockReg.blockExplosive` + `TileEntityExplosive#trigger` 改为 `state.getBlock() instanceof ExplosiveBlock`，触发点留 `// TODO(S3.09)`（平铺化后每种爆炸物一个方块、方块实体在 S3.09 才存在）。
5. **Forge `ExplosionEvent.Detonate`**：1.12 用它让监听器阻止实体伤害，端口没有对应事件（S3.02 已删 Forge 爆炸事件钩子），所以实体伤害总是执行；已在 `BlastTNT` 注释中说明。
6. **`Blast#getAffectedBlockPositions`**：1.12 从原版 `Explosion` 继承，S3.02 的 `Blast` 不再继承 → 本步在 `Blast` 中补回该列表与 getter（`BlastTNT`/`BlastBreach` 都用到）。
7. **`Mob#convertTo`**：`BlastMutation` 用 26.3 的转换 API 取代 1.12 的手工生成/`setDead`/`spawnEntity`（转换会 `addFreshEntity` 新实体并 `discard` 旧实体），`preventEntitySpawning` → `setPersistenceRequired()`、`setForgeProfession` → `setVillagerData`。
8. **时间修改**：`world.setWorldTime(18000/1200)` → 26.3 的按维度时钟（`clockManager().setTotalTicks(clock, ticks)`），无昼夜钟的维度跳过。
9. **`ExplosiveInit` 结构变化**：`newEx(tier, name)` → `newEx(tier, name, IBlastFactory)`，未移植的 11 个爆炸物改为 `todoBlast(name, "S3.0x")`（异常消息里带步骤号），全部 1.12 工厂表达式保持注释在调用点上方。

## 失败与修复

1. `BasicBlastsGameTest` 首轮 3 个失败：
   - `mutation`：断言写成了“原村民实体的类型变成僵尸村民”，但 26.3 `Mob#convertTo` 是“新建实体 + discard 旧实体” → 改为断言场景中出现 `ZOMBIE_VILLAGER`。
   - `endothermic`/`exothermic`：断言在 tick 0 立即执行，而 `BlastBeam` 要等两趟 worker（含 100 tick 计时）才变形方块 → 改为 `thenWaitUntil`（`maxTicks = 400`）。
2. 推拉两个用例：最初断言“5 tick 后与中心距离变大/变小”，但 1.12 的推力（`force = 半径*4 = 12`）会让目标**越过中心**（attractive 从 2.55 直接飞到中心另一侧 4.98），距离反而变大；`setNoAi(true)` 又会让生物完全不按 `deltaMovement` 移动。最终断言改为“冲量方向（外推/内拉）+ 5 tick 后沿推拉轴位移 > 1 格”，既确定又符合步骤卡意图（证据：失败输出里的距离/冲量/位移三元组）。
3. 编译期：`EntityType.ZOMBIE` 等常量在 26.3 已移到 `EntityTypes`（S3.01 已记录的事实），`Zombie` 的包为 `net.minecraft.world.entity.monster.zombie`，`CauseByTimer` 在 `content.actions.causeby` —— 全部按 javap/jar 目录核对后修正。

## 未覆盖 / 已知限制

- `rot` 的实际效果（方块替换）与断言留 S3.08（依赖放射性方块与替换表）；本步只保证 `BlastRadioactiveBlockSwaps` 的 worker/落地方案成立（编译 + 表解析路径）。
- `BlastBeam` 的“飞行方块先升起再放回”的完整时序只在 gametest 中断言了变形结果与飞行方块存在；升起的中间态与渲染留给 S4.07/S5.12。
- 线程化爆炸的**取消**：S1.09 线程池没有 per-task cancel，爆炸在 worker 仍在跑时结束不会取消该任务（1.12 的 `ThreadExplosion#kill` 语义在 S3.06 重建线程化爆炸时需要一并处理，已记入本文件）。
- `BlastBreach` 的方向默认值依赖 `HOST_DIRECTION` 字段（本步测试显式设置为 `UP`）；真实调用方（爆炸物方块/命令）在 S3.09/S3.10 提供方向。
- 未在图形客户端观察粒子/音效（S5.12 人工门禁）。
