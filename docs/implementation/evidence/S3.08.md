## 结果

- `icbmclassic:radioactive_dirt`、`icbmclassic:radioactive_stone` 注册（方块 + 物品 + 创造标签页 + 模型/掉落/标签/英文名）。
- 随机刻（`decay_delay > 0` 时）扩散替换与伤害行为与 1.12 一致；`rot` 爆炸的替换表改由 `RadioactiveHandler` 提供，`BlastRadioactiveBlockSwaps` 不再自带占位表。
- 1.12 `RadioactiveHandler` 的植被行（`Material.PLANTS/LEAVES/VINE` → 空气）用 26.3 方块标签表重建，须在数据包标签加载后 `setup()`，故挂在 `TAGS_LOADED`。

## 与步骤卡的差异

1. **两类方块各自注册**（卡片要求 `Kind` 构造）——与 ADR 0002 一致；`BlockRadioactive.properties(Kind)` 持有 1.12 的按类型硬度/抗爆数值与 `randomTicks()` 门控。
2. **测试用手动 `/icbm` 之外的路径**：`rotBlastSpreadsRadioactiveBlocks` 走真实 `rot` 爆炸（S3.04 线程化框架）等 400 tick；卡片提到的「手动 `randomTick`」未采用，另有 `radioactiveBlockDecayHurtsEntities` 直接验证 decay 伤害路径。
3. **`setup()` 时机**：卡片未指定；实现在 `CommonLifecycleEvents.TAGS_LOADED`（标签绑定后、服务端启动前），`RadioactiveGameTest#rotTableHoldsTheLegacyDefaults` 覆盖植被行，能捕获接错到 `onInitialize` 的回归。
4. **实体英文名**：`runDatagen` 的 `ICBMLanguageProvider#validate` 要求每个已注册实体类型都有英文名，S3.03/S3.06 的 `smoke`/`redmatter`/`fragment`/`flying_block`/`primed_explosive`/`light_beam`/`explosion_holder` 缺失（前几步未跑 datagen 故未暴露）。本步补 `ENTITY_NAMES`（1.12 无实体名，属端口新增，已在类注释说明），并把由生成侧提供的 `entity.icbmclassic.fragment` 从手写 `en_us.json` 移除。
5. **重复模型文件**：`src/main/resources/.../models/block/radioactive_{dirt,stone}.json` 与 datagen 输出逐字节相同，`processResources` 报 duplicate 后删除手写副本（资源迁移遗留）。
6. **`ModCreativeTabs`**：两个 BlockItem 放在 1.12 `ItemReg` 的方块物品收尾段（`MISSILE_MODULE` 之后、合成材料之前）。

## 失败与修复

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| `runDatagen` → `processResources`: `Entry assets/icbmclassic/models/block/radioactive_stone.json is a duplicate` | 资源迁移遗留的手写模型与 datagen 输出同路径 | 删除两个手写模型（内容相同） |
| `runDatagen` → `IllegalStateException: no English name for entity icbmclassic:smoke` | 实体类型缺英文名（差异 4） | `ICBMLanguageProvider` 增加 `ENTITY_NAMES` + 生成实体名 |

## 未覆盖 / 已知限制

- 放射性方块的**客户端表现**（材质、`animateTick` 的音效在客户端的可听性）属人工门禁（图形客户端实机）。
- `ConfigBlocks.radioactive.decayDelay` 的配置界面（1.12 Forge 配置 GUI）不在本轮范围。
- 1.12 `BlockRadioactive` 中保留的 TODO 与硬编码 20 tick wither 未改动（黄金规则：不修 1.12 缺陷）。
