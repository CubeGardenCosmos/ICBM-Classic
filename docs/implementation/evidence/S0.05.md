## 结果

- 完成判据「两次结果符合期望」：满足。干净时 `exit=0`；注入 `// EnumFacing` 后 `exit=1` 并打印违规行与模式；删除后恢复 `exit=0`。
- 禁用名扫描只覆盖 `src/`（不扫 `legacy-1.12/`），符合步骤卡；`src/main/java` 客户端 import 检查在干净状态下无输出。
- `scripts/check_lang.py` 尚不存在（S2.10 创建），`check.sh` 按步骤卡用 `[ -f ]` 跳过该段，不报错。
- 三项检查共用同一 `fail` 标志：禁用名或客户端 import 命中时即便 Gradle 构建成功，脚本仍以 1 退出（反向测试已证明）。

## 与步骤卡的差异

1. 步骤卡第 3 条列的 `/run/`、`/.dev/`、`/build/`、`.gradle/`、`/out/` 中，`.gitignore` 原有 `/run`、`build/`、`.gradle/`、`/out` 已覆盖（S0.03 又补了 `/.dev/`）；本步只补 `/src/main/generated/.cache/` 与 `*.log`。写法保持仓库既有风格（无尾斜杠的 `/run`、`build/`）。
2. `sonarCloudTrigger` 作业已删除；证据中注明“Sonar 作业删除，若需要由维护者另行配置”（步骤卡要求）。
