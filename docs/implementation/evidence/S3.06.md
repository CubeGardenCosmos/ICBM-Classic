## 与步骤卡的差异

1. **`BlastThreaded` 增加 `protected LevelSnapshot snapshot`**：步骤卡的 `doRun(int, Consumer<BlockPos>)` 签名没有快照参数，1.12 的子类则在各自线程里读世界。为使子类能在工作线程读方块，Sn 新增该字段（在 `doExplode` 里服务端抓取后赋值），两个子任务据此删除了各自的匿名 `ThreadWorkBlast` 变通写法；这是对 S3.04 基类的向后兼容增量（无 API 破坏）。
2. **红物质不引入快照/队列**：1.12 的红物质逻辑本来就在主线程（`Entity#onUpdate`）读写世界（`grep` 确认 legacy redmatter 无任何 Thread 用法），因此忠实移植为同步路径，只保留 1.12 的每 tick 预算常量（`DEFAULT_BLOCK_RAYTRACE_PER_TICK`、`MAX_BLOCKS_EDITS_PER_TICK`）；`RedmatterBlockCollector` 是无世界的整数数学静态工具。
3. **`DamageSourceRedmatter`**：1.12 的 `DamageSource` 子类语义（bypasses armor/absolute）已由 S3.02 的数据包伤害类型 + 标签承载，本类保留为薄包装以便调用点区分来源；若验收认为应彻底删除，需要改调用点（已登记）。
4. **`ThreadExplosion`/`ThreadLargeExplosion`/`ThreadSmallExplosion`（`content/blast/thread/**`）**：其收集逻辑分别并入 `BlastSonic`（S3.04）与 `BlastThreaded` 基类，三个旧类不再单独存在；账本相应行改为指向 `BlastThreaded#doRun`。
5. **“服务器停止时无残留工作线程”断言无法按要求实现**：`WorkerThreadManager` 只暴露 `startThreads`/`killThreads`/`addWork`，没有查询待处理工作量的方法（javap 已核对）。卡片要求的这条断言改为：`ICBMClassic#onInitialize` 已有的 `SERVER_STOPPING → killThreads()` 接线（S1.09）+ 三个 gametest 结束时线程池无任务堆积的间接证据（测试全部通过、无超时）。若需要显式断言，得先给 `WorkerThreadManager` 加只读访问器（超出本步范围，已登记）。

## 失败与修复

1. 首轮集成时 `ModEntities.REDMATTER` 尚未注册（红物质实体的主构造函数引用它）→ 主 Agent 在 `ModEntities` 补上 `redmatter` 注册（0.98×0.98、32 区块/1 tick、`MobCategory.MISC`），编译通过。
2. `BlastNuclear`/`BlastThermobaric` 最初各带一份匿名 `ThreadWorkBlast` 以获得快照 → 基类加 `snapshot` 字段后全部删除，逻辑收敛到一处。
3. 无 gametest 失败（三个用例首轮即通过）。

## 未覆盖 / 已知限制

- `EntityRedmatter` 的移动/合并路径只有编译期与 gametest 的“生成后吸走附近方块”级验证（`ThreadedBlastsGameTest` 未断言红物质实体本身，卡片也未要求）；1.12 的 TODO 明确该逻辑不完整，保持原样。
- 红物质的客户端渲染（`render/**`）按步骤卡排除，改成 26.3 渲染器属 S4.07。
- `BlastAntimatter` 的“杀死范围内红物质”分支在 gametest 中未构造两颗红物质对撞场景，只验证了基岩清除。
- 线程池的取消语义（1.12 `ThreadExplosion#kill`）在 S1.09 框架下没有对应物：爆炸提前结束时正在跑的 worker 仍会跑完并写回一个已死爆炸的列表（不会被执行）；这是**已知行为差异**，若验收要求严格取消，需要给 `WorkerThreadManager` 增加 per-task 取消（超出本步）。
