## 与步骤卡的差异

- 失败断言的正确修复是等待瞄准而非改 launcher state machine。legacy `CLauncherCapability.java:89-96` 明确先设置 target；若 `!host.isAimed()` 就保存 `FiringPackage` 并返回 `LauncherStatus.FIRING_AIMING`。legacy `TileCruiseLauncher.java:181-203` 每 tick 转动 `currentAim`，并在 `firingPackage != null && isAimed()` 后递减倒计时、调用发射。因此 `launch()` 首次调用时返回瞄准状态是正常预发射行为；该状态为 blocking（当前状态实现 `LauncherStatus.java:26`）。新代码对应 `CLauncherCapability.java:95-100` 与 `TileCruiseLauncher.java:168-177` 保留该状态机。本测试改为断言返回 `FIRING_AIMING`，之后仍用异步 `succeedWhen` 断言导弹实体出现和目标方块被摧毁；未删除覆盖或放宽为非阻塞状态。
- 步骤卡要求 `RadioCruise` 对 `IIncomingMissileMessage` 的处理原样保留，但指定的 legacy `RadioCruise.java` 不导入/处理该消息：完整 `onMessage` 分支 `34-67` 只处理 `ITargetMessage` 与 `ITriggerActionMessage`。因此不凭卡片新造 legacy 中不存在的 incoming 行为；移植保留了 legacy 实际存在的目标、发射触发及触发回调（当前代码 `RadioCruise.java:36-83`）。这与 S7.06 卡里该行为后续删除的描述亦说明卡片本身不一致，需验收时留意。
