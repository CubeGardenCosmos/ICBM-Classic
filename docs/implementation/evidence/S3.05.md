## 结果

- 完成判据（步骤卡 S3.05）：
  1. **气体爆炸可用**：`BlastGasBase`（扩云/路径/粒子/实体扫描/防护门槛）+ `BlastDebilitation`、`BlastChemical`、`BlastContagious`、`BlastColor` 全部移植；`ExplosiveInit` 中这 5 个爆炸物（debilitation、chemical、contagious、colors、smoke）换成真实工厂。
  2. **自定义效果注册**：`content/reg/ModEffects` 注册 4 个效果（`toxin`、`virus`、`frost_bite`、`radiation`），id 与既有 `effect.icbmclassic.*` 语言键一致，`ICBMClassic#onInitialize` 调用 `ModEffects.register()`。
  3. **防护装备判定可用**：`ProtectiveArmorHandler` 读 `ConfigMain.protectiveArmor`（`item_ratings` 为 `domain:resource=float` 列表，`require_helmet` 生效），gametest 断言“达到阈值的不受毒、未达的受毒”。
  4. **解毒剂**：`ItemAntidote` 的 S2.04 占位 TODO 填实，`finishUsingItem` 清除 4 个 ICBM 效果 + 1.12 气体用到的原版效果；gametest 断言清除生效。
  5. **smoke 爆炸**：`ActionSpawnEntity` 移植并注册到 `ACTION_REGISTRY`（`icbmclassic:entity.spawn`，`ActionSystem.setup()`），smoke 工厂按 1.12 表达式返回该动作；gametest 断言生成 `smoke` 实体。
- 验证：`runGameTest` 70/70（两次）；`check.sh` exit 0；无残留游戏进程（`./gradlew --stop` 已执行）。

## 与步骤卡的差异

1. **`CustomPotion` → DROPPED**：1.12 中它是抽象类且没有任何具体子类（已 grep 确认），自注册进 `Potion` 注册表的逻辑由 `ModEffects.register()`（`Registry.registerForHolder`）取代；`CustomPotionEffect` 保留同名包装（26.3 的 `MobEffectInstance` 已无 curative 列表，差异写在类注释里）。
2. **四个效果的行为来源**：1.12 只有 4 个语言键（`potion.toxin/virus/frostBite/radiation`）而没有对应的 `Potion` 实例。端口按步骤卡要求把它们注册成真实 `MobEffect`，行为取 1.12 代码里对应的效果集合：
   - `toxin` ← chemical 气体原本要施加的“Chemical”毒集合（POISON 30s + NAUSEA + HUNGER + WEAKNESS + MINING_FATIGUE，1.12 TODO “was toxin potion”）；
   - `virus` ← contagious 气体集合（POISON 45s + BLINDNESS 15s + HUNGER/WEAKNESS/MINING_FATIGUE）并带传染扩散；
   - `frost_bite` ← 冷冻语义（缓慢/挖掘疲劳，对应 endothermic 的冷效果）；
   - `radiation` ← 周期性辐射伤害（对应放射性方块/核爆）。
   每个效果的实现理由与取舍逐条写在对应类注释，属**解释性决策**，已在此登记以便验收复核。
3. **解毒剂清除清单**：1.12 的 `onItemUseFinish` 清除**全部**效果，端口改为显式清单（4 个 ICBM 效果 + 气体用到的原版效果），好处是增益效果（如再生）不再被误清；差异写在类注释与本文件。若验收要求严格等价，需要人工裁决。
4. **`Poison`/`ContagiousPoison` 的形态**：不再继承 `Potion`，改为“效果应用器”（保留 name/id 映射与 creative/护甲判定），因为 26.3 的效果必须注册为 `MobEffect` 且 `Potion` 类已不存在。
5. **配置路径**：防护装备 `item_ratings` 从 1.12 的 `icbmclassic/main/protective_armor/item_ratings`（TOML 路径）改为 `config/icbmclassic/main.json#protectiveArmor.item_ratings`（`@ConfigEntry`），解析仍走 S1.02 移植的 `ItemStackConfigList`；`@meta` 后缀在 26.3 不再支持（列表项直接写 `namespace:path=float`）。
6. **`lib/colors/{ColorB,ColorHelper}`**：`BlastColor` 的硬依赖，账本原行没有分配步骤（`—`），本步随 colors 爆炸一并移植并补账本，属必要的范围补齐而非新功能。
7. **粒子**：1.12 的气体粒子用颜色工厂，端口改 `ServerLevel#sendParticles(ColorParticleOption.create(ParticleTypes.ENTITY_EFFECT, r, g, b), ...)`，颜色/数量/扩散按 1.12 值换算（子任务在报告里给了逐项对照）。

## 失败与修复

1. `chemicalBlastPoisonsZombie` 首轮断言用了原版 `POISON`，实际端口把 1.12 的“Chemical 毒集合”落在注册的 `TOXIN` 效果上 → 断言改为 `ModEffects.TOXIN`（并在注释里写明来源）。
2. 气体测试间歇性失败（同一套用例两次运行分别失败在 chemical / debilitation）：僵尸的 AI 会把它走出气体云半径，结果取决于巡逻路径。修复：测试中的僵尸 `setNoAi(true)` 固定在中心，`maxTicks` 提到 800；两次连续运行均 70/70。
3. 编译期小修：`ConfigMain.protectiveArmor` 的字段名不是全大写下划线而是驼峰 `minProtectionChemicalGas`（按端口配置类实际字段修正）；解毒剂物品引用改为 `ModItems.ANTIDOTE`。

## 未覆盖 / 已知限制

- 四个自定义效果的具体数值平衡（持续时间/伤害/传染范围）是按 1.12 代码与名称推导的**首次实现**，没有实机玩法验证；验收若认为行为不符，需要人工给出期望值。
- `virus` 的“传染”扩散半径在 gametest 中未单独断言（只在气体云用例中验证了效果施加），因为 1.12 的传染分支本身没有可测的配置开关。
- 气体云的路径算法与粒子外观未在图形客户端观察（S5.12 人工门禁）。
- `BlastColor` 的染色效果只在编译与基础用例层面验证（其 gametest 未单独列出，卡片也未要求具体断言）；如需可后续补测。
