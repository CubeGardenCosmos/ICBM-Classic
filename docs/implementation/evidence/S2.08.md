## 结果

- 完成判据：满足。1.12 全部 129 个 JSON 配方逐条分类：111 条在 26.3 生成（输入改标签/直接引用），
  15 条因输出物品尚未注册留待 S5/S6，4 条因依赖 26.3 不存在的资源（铀/碳粉/兜底版本）由等价版本替代，5 个特殊
  `IRecipe` 标 → S4.06。

## 与步骤卡的差异

1. **`buildRecipes()` 必须是 `public`**：`javap` 显示 `protected abstract void buildRecipes()`，但 javac 在 Loom 的
   编译类路径上看到的是 `public`（`attempting to assign weaker access privileges; was public`），因此实现为 `public`。
2. **`_factories.json` 的两种工厂在本步直接翻译、不作为「特殊配方」跳过**：步骤卡第 4 条把它们列在「只列出不实现」，
   但 `ExRecipeFactory`/`ExIngredientFactory` 只是「按元数据解析装置栈」的机制，ADR 0002 平铺化后等价于普通物品配方
   （步骤卡第 3 条也要求这样翻译）；真正需要自定义代码的是 5 个 `IRecipe` 类（上表 → S4.06）。
3. **`treeLeaves|treeSapling` 的一个 OR 拆成两条配方**（`saltpeter_ball` 与 `saltpeter_ball_from_saplings`）：
   26.3 没有同时含树叶与树苗的标签，`Ingredient` 只能是单个标签或原版物品集合。
4. **`RecipeCategory` 是新加的**：1.12 没有配方分类，按输出类型选择（方块→`BUILDING_BLOCKS`/`REDSTONE`，
   战斗类物品→`COMBAT`，材料→`MISC`，解毒剂→`FOOD`，矿车→`TRANSPORTATION`）。
5. **`unlockedBy` 是新加的**：26.3 每条配方必须有解锁判据；统一用「代表性原料」（原版物品或对应标签）生成。

## 未覆盖 / 已知限制

- 配方解锁体验（配方书里何时出现）未逐个复刻 1.12（1.12 通过 `forge:ore_dict` 条件而非进度解锁）。
- 未实现 15 条依赖 S5/S6 内容的配方；`emp_explosive` 的原料 `battery` 在 S6 落地后需补配。
- 未做 JEI/REI 联动（S7 范围）；合成结果的实际物品行为（导弹/手雷仍是 S2.05 的占位物品）由 S4 接管。
- 特殊配方（集群/携带物品/货物数据/拆解）在 S4.06 实现前，这四种交互不可用。
