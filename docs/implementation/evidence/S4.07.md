## 结果

- 每个 `ModEntities` 注册的实体类型都有渲染器：EXPLOSION_HOLDER/SMOKE/MISSILE_SEAT → 原版 `NoopRenderer`；PRIMED_EXPLOSIVE/REDMATTER/FLYING_BLOCK/LIGHT_BEAM/FRAGMENT → S4.07-s3 已移植的渲染器；EXPLOSIVE_MISSILE/GENERIC_MISSILE/MISSILE_SAM/HELD_ITEM_MISSILE → `RenderMissile`；GRENADE/BALLOON → `RenderAsItem`；PARACHUTE → `RenderParachute`；BOMB_DROPLET → `RenderBombDroplet`；BOMB_CART → 原版 `TntMinecartRenderer`。启动自检（`IcbmEntityRenderers#validateRenderers`）在**渲染器构建完成后**（`END_CLIENT_TICK` 里先用原版类型探针确认 dispatcher 已就绪，再检查一次）遍历 icbmclassic 命名空间并报出缺失项，日志行 `Checked the renderer of N icbmclassic entity types`（期望 N=17，与 ModEntities 的注册数一致）。**注意**：首版自检挂在 `CLIENT_STARTED`，早于渲染器构建，会误报全部 17 个类型缺失（见下节实机反馈）。
- 粒子：`icbmclassic:smoke_icbm` 注册（main）+ provider（client）+ 粒子贴图定义；`AirParticlePayload`（毒气云）与 `BlockExplosionFxPayload` 从“只打日志”改为真实粒子；导弹引擎/发射台烟雾按 tick 生成。
- 太空鸡头盔：模型层注册 + 自定义鸡渲染器/渲染状态 + 附件同步。
- `bash scripts/check.sh` 全绿；GameTest 123/123（渲染器与粒子不参与服务端流程，未新增用例）。

两个缺陷，均已修复：

1. **`RenderItemImp` 的静态 `ItemStack`（黑屏直接原因）**：1.12 的 `BACKUP_RENDER_STACK`（`Blocks.FIRE`）被写成 `private static final ItemStack`，26.3 的实体渲染器在**首次资源重载**里构建，早于物品组件绑定，静态初始化抛 `Components not bound yet` → 渲染线程异常 → 黑屏。修复：改为渲染器实例字段 + 首次使用时懒加载（`getBackupRenderStack()`）。
2. **自检时机错误（误报）**：`CLIENT_STARTED` 早于 `EntityRenderDispatcher.onResourceManagerReload`（日志时间 23:23:38 vs 23:23:41），此时 dispatcher 尚无任何渲染器，故 17 个类型全是假阳性。修复：改挂 `ClientTickEvents.END_CLIENT_TICK`，先用原版类型（`EntityTypes.CHICKEN`）探针确认 dispatcher 已就绪，再执行一次检查。

两处修复后复跑：`bash scripts/check.sh` → EXIT=0、GameTest 123/123、lang 432（日志 `.dev/tmp/check-fix2.log`）。修复后构件 MD5 `3226ca8c95230aa9652003c5934696e8`，已重新部署到客户端/服务端 mods 与 G 盘根目录；实机复测结果待人工确认（届时日志应出现自检行且**没有** `No renderer registered`）。
