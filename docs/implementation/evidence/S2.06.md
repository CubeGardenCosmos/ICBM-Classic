## 26.3 图集修正（实机冒烟发现）

26.3 的模型烘焙只允许一个图集：贴图目录决定图集（`textures/item/**` → `items.png`，`textures/block/**` → `blocks.png`），
同一模型混用会报 `IllegalStateException: Multiple atlases used in model, expected minecraft:textures/atlas/items.png,
but also got minecraft:textures/atlas/blocks.png`，该物品会退化为紫黑模型。1.12 的 5 个导弹模型 + 1 个 1.12 资源缺陷踩了这个坑，
由无图形客户端冒烟测试（`./gradlew runClient`，见下）发现：

| 模型 | 1.12 混用的贴图 | 处理 |
| --- | --- | --- |
| `item/missiles/endothermic` | `items/missiles/tier3` + `blocks/cryo_flow` | 自有方块贴图移到 `item/missiles/cryo_flow`（含 `.mcmeta`），模型留在物品图集 |
| `item/missiles/redmatter` | `items/missiles/redmatter_body` + `blocks/redmatter_flow` | 同上，移到 `item/missiles/redmatter_flow` |
| `item/missiles/antimatter` | `items/missiles/antimatter` + `blocks/antimatter` | 同上，移到 `item/missiles/antimatter_block`（避免与已有 `item/missiles/antimatter.png` 重名） |
| `item/missiles/anvil` | `items/missiles/tier1` + `minecraft:blocks/anvil_base` | 保留原版方块贴图（不改版 1.12 外观），把自有贴图复制到 `block/missiles/tier1`，模型整体改用方块图集 |
| `item/missiles/exothermic` | `items/missiles/tier3`、`items/missiles/exothermic` + `minecraft:blocks/lava_flow` | 同上，复制到 `block/missiles/{tier3,exothermic}` |
| `item/missiles/attractive` | 元素 `cubeN` 的 west 面引用了未定义的 `#missing`（1.12 资源缺陷） | 改为该元素其它面使用的 `#1` |

未迁移到 `item/` 的 3 个原版引用不做替身贴图（原版贴图的复制涉及资源授权）；`cryo_flow`/`redmatter_flow`/`antimatter`
只被上述导弹模型引用（`grep -rl` 全 legacy 资源树确认，Java 代码无引用），因此是移动而非复制。
`check_assets.py` 增加了「单模型图集一致」静态检查，防止回归。

## 与步骤卡的差异

1. **不能用原版生成器辅助方法**：26.3 的 `BlockModelGenerators` 只公开构造器 + `createTintedLeaves`/`createParticleOnlyBlock`/`run`，
   `createTrivialCube`/`createFlatItemModel`/`registerSimpleItemModel`/`createButton` 全是 private，`ModelProvider` 也没有
   `registerModels` 扩展点。因此 `ICBMModelProvider` 自建 `DataProvider`：用公有原语（`ModelTemplate.create`、
   `MultiVariantGenerator`、`BlockFamilyProvider`）产出三份收集器内容，再用原版 codec（`BlockStateModelDispatcher.CODEC`、
   `ClientItem.CODEC`、`ModelInstance#get`）与 `DataProvider.saveAll` 落盘，格式与 `ModelProvider` 一致。
2. **压力板物品模型要自己加**：`BlockFamilyProvider.pressurePlate(Block)` 只生成两个模型与方块状态，不注册物品模型
   （与 `button(Block)` 不同），故显式 `blockItemModel(GLASS_PRESSURE_PLATE, ModelLocationUtils.getModelLocation(...))`，与
   原版 `items/stone_pressure_plate.json` 指向 `block/stone_pressure_plate` 一致。该缺口由 provider 的 `validate()` 抓出
   （`Missing model definitions: [item icbmclassic:glass_pressure_plate]`）。
3. **datagen 入口不注册内容**：fabric-api 的 datagen 在客户端启动流程内被调用，loader 已先执行 `main` 入口点，重复注册会
   撞上 `Registry is already frozen`；`ICBMDataGenerator` 只做非空守卫（`ModBlocks.CONCRETE`/`ModItems.MISSILE_MODULE`），
   入口顺序变化会得到明确报错而不是空资源树。
4. **`build.gradle` 多写一项 `addToResources = true`**：步骤卡只要求 `configureDataGeneration { client = true }`；
   显式打开该项把 `src/main/generated` 挂到 main 资源上（jar 内与 GameTest classpath 都能读到生成物），
   否则 `items/<id>.json` 检查无法成立。
5. **机器方块只复制模型，未生成方块状态**：S5 之前机器方块未注册，`MultiVariantGenerator.dispatch(block, ...)` 需要真实
   `Block` 实例，无法 datagen；16 个机器方块模型按步骤卡第 4 条先复制并改写纹理，方块状态随 S5 注册时生成。
6. **尖刺用 `minecraft:block/cross`**（`ModelTemplates.CROSS`）替代 1.12 的 `block/tinted_cross`：26.3 尖刺贴图不需生物群系着色，
   几何等价，且省掉自建模板。
