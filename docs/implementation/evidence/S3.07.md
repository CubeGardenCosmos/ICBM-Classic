## 结果

- EMP 与末影爆炸两个爆炸物进入注册表并可用（`icbmclassic:emp`、`icbmclassic:ender`）。
- EMP：苦力怕充能（1.12 `CapabilityEmpCreeper` → `Creeper#thunderHit`）、掉落物与容器内物品经 `CapabilityEmpInventory` 逐槽调用接收器并写回、点燃炸药被击杀（`CapabilityEMP` 注册到模组实体类型）、配置替换表生效。
- 末影：`ExplosiveSettings#enderTarget` 决定落点，未设目标时按 1.12 行为随机寻点（客户端渲染属 S4.07）。

## 与步骤卡的差异

1. **步骤卡要求「`ActionDataEmpArea` 注册进动作表」** —— 已注册为 `icbmclassic:emp.area`；1.12 无动作注册表，`REG_NAME` 为端口新增（命名规则沿用 `icbmclassic:entity.spawn`）。
2. **EMP 接收器注册点**：模组自身的 `primed_explosive` 不能在 `CapabilityEMP.register()`（`IcbmLookups.init()`）注册——此时 `ModEntities.PRIMED_EXPLOSIVE` 仍为 `null`，`EntityApiLookup.registerForTypes` 会抛 `NullPointerException: Key may not be null`（实测）。改为在 `ModEntities#register()` 建好类型后注册，行为等价。
3. **`CapabilityEmpInventory` 物品内层库存**：1.12 只在物品自身带 Forge 物品库存 capability 时进入 `ItemInvInEntity`/`ItemInvInTile`，26.3 具备「物品内库存」的 DataComponent 尚未移植，故该分支不可达；直接复用宿主容器会无终止递归（1.12 亦有此隐患，只是当时无物品注册该 capability）。保留 1.12 语义为注释 + `TODO(S3.07)`。
4. **配置字符串形式已知缺陷（1.12 原样保留，未修）**：`ResourceConfigList#KEY_VALUE_REGEX = ^([^\s@]*):([^\s=]*)(?:=(\S*))?` 的域名组会吞掉目标里命名空间的 `=`，`minecraft:stone=minecraft:gold_block` 被解析成域名 `minecraft:stone=minecraft` → 报 `No matching mod domain found`。1.12 连正则带 `ConfigEmp.BlockReplacements#blockStates = new String[]{}` 默认值完全相同，属 1.12 既有缺陷（黄金规则：不在移植步骤里修 1.12 缺陷），本步仅把 `EmpBlastsGameTest#empReplacesConfiguredBlocks` 改为经 `BlockStateConfigList#setDefault(...)` 注入同一行，走的是同一条 `getValue` → `BlockReplacementData#apply` 路径。
5. **末影传送 26.3 映射**：1.12 `EntityPlayerMP#setPositionAndUpdate` 的落点外推不可用，改用 `Entity#teleportTo(ServerLevel, ...)`（同维度直接落点，跨维度由 `ServerLevel` 提供）；`BlastEnder` 头注记录了逐行对照。
