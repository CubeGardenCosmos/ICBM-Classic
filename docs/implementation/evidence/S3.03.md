## 结果

- 完成判据（步骤卡 S3.03）：
  1. **实体类型注册齐全**：`fragment`（3 区块/1）、`flying_block`（8/1）、`primed_explosive`（4/5）、`light_beam`（5/5）、`smoke`（7/15），尺寸取 1.12 `setSize` 值（0.5×0.5、0.98×0.98、0.98×0.98、1×1、1×1），`ModEntities` 新增 `registerEntity(...)` 帮助方法统一处理 `EntityType.Builder` + 区块单位换算。
  2. **碎片**：三种模式（箭/铁砧/爆炸）保留，`setExplosive/setAnvil/setDamage` 保持链式 1.12 API；伤害源沿用 1.12 的原版 arrow 类型（1.12 代码里的 TODO 未修）；gametest 覆盖重力飞行、扎入方块、爆炸模式落地与存档往返。
  3. **飞行方块**：`EntityFlyingBlock extends EntityProjectile`，携带的 `BlockState` 走 `EntityDataSerializers.BLOCK_STATE`；gametest 断言“落地把方块放回世界 + 实体移除”与“方块状态/源物品/重力在存档往返后相等”。
  4. **点燃炸药**：`EntityExplosive` 持有爆炸 id（`Identifier`，同步为字符串）与引信（同步 int），引信到时按 1.12 链路走 `EXPLOSIVE_REGISTRY → IExplosiveData#create → IAction#doAction`；gametest 只断言生成/字段/引信递减/存档往返，**不含爆炸断言**（见“与步骤卡的差异”）。
  5. **光束与烟雾**：`EntityLightBeam`/`EntitySmoke` 的公开字段（1.12 渲染器直接读）保留，靠 `updateDataBeforeSync()`+`onSyncedDataUpdated` 与 `SynchedEntityData` 双向同步；烟雾粒子改 `ServerLevel#sendParticles(ParticleTypes.SMOKE, ...)`，数量/速度换算与 1.12 `spawnParticle` 等效。
- 验证：`runGameTest` 51/51；`check.sh` exit 0；无残留游戏进程（`./gradlew --stop` 已执行）。

## 与步骤卡的差异

1. **`primed_explosive` 的爆炸断言推迟到 S3.04**：步骤卡要求“引信设 1 tick 后附近石头消失”，但 `ExplosiveInit#todoBlast` 的全部工厂在 S3.04 前仍是抛异常的占位符（S2 的既有约定），无法在本步触发真实爆炸。本步改为断言“生成 → 字段/引信正确 → 引信递减 → 存档往返”，并在测试中注明爆炸断言由 S3.04 的 `BasicBlastsGameTest` 覆盖（步骤卡 S3.04 的断言列表里已包含 condensed“至少 1 个石头变空气”）。**未缩小范围，只是把断言交接到包含它的那一步。**
2. `EntityExplosion`（爆炸持有实体）已在 S3.02 完成，本步只做剩余 5 个实体。
3. 1.12 的 `IEntityAdditionalSpawnData` 全部删除：需要客户端可见的值（模式、颜色、光束进度、方块状态、爆炸 id/引信/朝向）进 `SynchedEntityData`，其余进 `SaveHandler`；`preventEntitySpawning`/`ignoreFrustumCheck`/`canTriggerWalking` 在 26.3 无对应物，分别由数据驱动生成/渲染器 `shouldRender`（S4.07）负责，已在类注释说明。
4. `EntityFlyingBlock` 的重力钩子从 1.12 `getGravity()`/`setGravity()` 改名 `getProjectileGravity()`/`setProjectileGravity()`（26.3 `Entity#getGravity()` 是 final，沿用 S3.01 的命名）。
5. `FlyingBlock.spawnFlyingBlock` 的回调顺序保持 1.12（在 `addFreshEntity` 前把方块状态推进同步数据，等价旧 spawn data 时机）。
6. `BlockCaptureData` 的 `INBTSerializable<nbt>` → `ISavable`，键名 `block_state`/`source_stack`/`block_entity` 不变。
7. `EntitySmoke`/`EntityLightBeam` 的 1.12 存档方法本身为空或缺字段，端口按字段表补齐 `SaveHandler`（键名沿用 1.12 字段名），已在类注释与账本说明。
8. 新增语言键 `entity.icbmclassic.fragment`（碎片实体名，原 1.12 由实体注册名生成显示名）。

## 失败与修复

1. 首次 `runGameTest`：51 个用例中 `flying_block_game_test_flying_block_survives_save_round_trip` 报 “Didn't succeed or fail within 100 ticks” —— 该用例缺少 `helper.succeed()`，补上后通过（这是测试写法问题，不是实体行为问题）。
2. `scripts/check.sh` 的禁用名扫描命中 12 处**注释**里的 1.12 类型名（`IBlockState`/`NBTTagCompound`/`TileEntity`/`EntityPlayer`/`EnumFacing`），全部改写为不含禁用 token 的等效说明后扫描通过。黄金规则 §2.4 对 src 下任何出现都零容忍，注释同样适用。
