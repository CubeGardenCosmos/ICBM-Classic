## 签名核对

| 依赖面 | 1.12 用法 | 26.3 用法（已 `javap`/`mcsrc.py` 核对） |
| --- | --- | --- |
| 入口 | Forge `ICommand` + `CommandEntryPoint`（`register(ICommand)`） | `CommandRegistrationCallback.EVENT.register((dispatcher, registryAccess, environment) -> ICBMCommands.init(dispatcher))` |
| 权限 | `getRequiredPermissionLevel() == 2` | `Commands.literal("icbm").requires(Commands.hasPermission(Commands.LEVEL_GAMEMASTERS))`；`LEVEL_GAMEMASTERS` → `PermissionCheck.Require(Permissions.COMMANDS_GAMEMASTER)` = `HasCommandLevel(GAMEMASTERS)` |
| 参数 | 手工 `CommandUtils.parseXxx(String[])` | `IdentifierArgument.id()`、`DimensionArgument.dimension()`、`Vec3Argument.vec3(false)`、`IntegerArgumentType`/`FloatArgumentType` |
| 补全 | `getTabCompletionOptions()` 返回字符串数组 | `SuggestionProvider`（`SharedSuggestionProvider.suggest`） |
| 控制台判定 | `sender instanceof MinecraftServer` | `CommandSourceStack#getEntity() == null`（26.3 的 `CommandSourceStack` 不暴露 `CommandSource`，Fabric 访问放宽器也没有该项，`javap -p` 已核实） |
| 执行 | `/icbm ...` 经 Forge 分发给 `CommandGroup#handleCommand` | `MinecraftServer#getCommands().performPrefixedCommand(CommandSourceStack, String)`（去可选前导 `/`，同步执行）；语法错误由 `ExecuteCommand` 捕获 → `sendFailure`，不会抛出到调用方 |

## 结果

- `/icbm help`、`/icbm blast {help,list,trigger,spread}`、`/icbm remove`、`/icbm lag` 全部可用，参数、权限等级（2）、补全与 1.12 一致。
- 输出文本使用 S2.10 迁移的 `icbmclassic.command.*` 键；help 与 `blast list` 保持 1.12 的字面量输出（1.12 同样没有翻译键）。

## 与步骤卡的差异

1. **`/icbm blast trigger`**：卡片正文写作 `/icbm blast <explosive> <pos> [scale]`，但 1.12 的子树是 `blast → {trigger, spread, list}`（`legacy-1.12/.../command/ICBMCommands.java#initBlastCommand`、`CommandBlastTrigger#super("trigger")`）。按黄金规则保持 1.12 结构，未额外加短形态。
2. **格式符 `%d`/`%f` → `%s`**（S2.10 迁移遗留缺陷）：26.3 `TranslatableContents#decomposeTemplate` 只接受 `%s` 与 `%%`（`javap -c` 显示字形判断只有 `s`，其余抛 `TranslatableFormatException`，客户端随后渲染原始模板）。因此 `icbmclassic.command.lag.remove`、`icbmclassic.command.remove`、`icbmclassic.command.spread.started` 三个值改为 `%s`（其中 1.12 的 `icbmclassic.command.remove` 本身是 `%1%d` 拼写错误，1.12 时输出原始键）。**同一缺陷还影响尚未移植消费方的键**（`icbmclassic.message.radar_gun.scanned` 的 `%x %y %z %d`、`icbmclassic.radio.*` 的 `%1$f`），那些属 S5 范围，未在本步改动。
3. **新增两条英文文本**：`icbmclassic.message.launcher.toolTargetSet` / `noTargetInTool` 由 S3.09 的末影 GPS 激活使用，1.12 的 `en_US.lang` 缺这两条（只有 ru/de 有），按 i18n 规则在 `en_us.json` 补齐英文，`check_lang.py` 才能通过。
4. **控制台判定**：26.3 无法从 `CommandSourceStack` 读回 `CommandSource`，改用 `getEntity() == null`。后果：控制台保持 1.12 行为；命令方块/函数（1.12 视为世界内发送者）现在也需要长式参数。已在 `CommandUtils#isConsoleSender` javadoc 记录。
5. **维度参数**：1.12 用数字维度 id（含 `~`），26.3 改 `DimensionArgument.dimension()`（标识符补全，无数字 id、无 `~`）；spread 消息里的「世界类型名」改为维度标识/维度类型注册名，参数顺序不变。
6. **位置参数**：1.12 `CommandUtils.getNumber` → `Vec3Argument.vec3(false)`；绝对数原样使用（不加 0.5，与 1.12 相同），`~` 相对命令源位置。
7. **有意修复的 1.12 缺陷**：`CommandBlastTrigger#getExplosive` 在 1.12 经 `ICBMClassicHelpers#getExplosive(id, true)` 查询，而该 helper 对未知 id 会回退到 condensed，使「Explosive with ID '%s' could not be found」分支永不可达、错误 id 静默执行 condensed。本步按步骤卡要求（未知 ID 返回失败）改为允许返回 null 的查询，使 1.12 的错误消息真正生效；已在方法 javadoc 记录。
8. **1.12 缺陷保留**：`icbmclassic.command.spread.started` 的参数/占位错配（`%4$d` 位置给的是世界类型名）原样保留；状态文本仍来自 `result.message()`（1.12 `result.getTooltip()`）；help/`blast list` 不翻译。
9. **未使用的 1.12 常量删除**：`TRANSLATION_TRIGGERED`/`TRANSLATION_THREADING` 与 `.error/.blocked/.null/.triggered/.unknown` 键在 1.12 亦无引用。
10. **`CommandUtils#isICBMEntity`** 暂不含 `EntityBombDroplet`/`EntityGrenade`（S4/S5 才移植），1.12 的 `//TODO just check for ICBM namespace` 保留。

## 失败与修复

| 现象 | 根因 | 修复（均在 GameTest 侧，产品代码无改动） |
| --- | --- | --- |
| `command_game_test_blast_trigger_command_removes_stone` 等 6 例报 `Incomplete (expected 3 coordinates)` | 测试用 `Double.toString` 拼坐标；结构原点跨过 ±1e7 时输出 `-1.00748645E7`，Brigadier `StringReader#readDouble` 不支持指数写法（实测：`Expected double at position 11: ...1.00748645<--[HERE]`），`WorldCoordinate.parseDouble` 捕获后抛 `argument.pos3d.incomplete`。结构原点在 1e7 以内时测试偶发通过 | `position()` 改用 `String.format(Locale.ROOT, "%.1f %.1f %.1f", ...)` |
| `remove/lag` 报 `Removed 0 entities within 4 meters` | `GameTestHelper#spawn(EntityType, Vec3)` 的坐标经 `GameTestHelper#absoluteVec` 解析，即**相对结构原点**（与 `setBlock(BlockPos)` 同约定），测试却传了绝对坐标 → 实体生成在结构原点外 | `spawnPrimedExplosive` 改传结构相对坐标 |
| `nuclear_explosive_is_primed_with_the_registry_fuse` 报 `fuse is -1` | 引信由点燃实体第一 tick 初始化（1.12 `EntityExplosive#onUpdate`: `if (fuse == -1) fuse = registry.getFuseTime(...)`），测试在生成当 tick 断言 | 断言前 `thenWaitUntil` 等 `getFuse() > 0` |
