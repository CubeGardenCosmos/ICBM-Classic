关键 javap 结论（与骨架/文档不同的地方）：

1. `Container` 的抽象集合是 `getContainerSize`/`isEmpty`/`getItem`/`removeItem(int,int)`/`removeItemNoUpdate`/`setItem`/`setChanged`/`stillValid(Player)`（另有 `clearContent` 来自 `Clearable`）——步骤卡列出的方法名全部存在。
2. `ContainerHelper.saveAllItems/loadAllItems` 接受 `ValueOutput`/`ValueInput` + `NonNullList<ItemStack>`（正是步骤卡猜测的形态）。
3. 标准玩家槽位助手是 `AbstractContainerMenu#addStandardInventorySlots(Container, int, int)`（不是 `addStandardSlots`）。
4. `AbstractContainerScreen` **没有** `extractBackground`：变暗背景在 `Screen#extractBackground`，容器面板由 `extractContents` 画（`extractRenderState` → `extractContents` → `extractLabels` → `extractSlots` → `extractTooltip`），所以面板改在 `extractBackground` 覆写里画（先 `super` 变暗层，再画面板，与 1.12 顺序一致）。
5. `Entity#hurtServer(ServerLevel, DamageSource, float)` 是 abstract，`EntityICBM` 必须实现它（1.12 `attackEntityFrom` 的对应物）。
6. `BlockBehaviour#affectNeighborsAfterRemoval` 在 `removeBlockEntity` **之后**调用（`LevelChunk#setBlockState`：`preRemoveSideEffects` → `removeBlockEntity` → `affectNeighborsAfterRemoval`），因此 1.12 `BlockICBM#breakBlock` 的掉落无法在方块层实现；26.3 用 `BlockEntity#preRemoveSideEffects`（默认就会掉落 `Container` 内容）。
7. `Containers.dropContents(Level, BlockPos, Container)` **不清空**容器（只读 `getItem` 后掉落），所以 `InventoryUtility.dropInventory` 自己用 `removeItemNoUpdate` 取出并掉落，避免与 `preRemoveSideEffects` 双倍掉落。
8. `org.lwjgl.glfw` 不在编译类路径，插入键常量用 `com.mojang.blaze3d.platform.InputConstants.KEY_INSERT`。
9. `Screen`/`GuiScreen` 的修饰键静态方法已移除，改用 `Minecraft#hasShiftDown()`/`hasAltDown()`。
10. `EditBox#setFocused` 内部已调用 `Minecraft#onTextInputFocusChange(GuiEventListener, boolean)`（javap -c 可见两处调用），因此 `TextInput` 覆写 `setFocused` 时保持 `super` 即可满足步骤卡 §5 的 SDL 焦点要求。

## 与步骤卡的差异

1. **GUI 面板的绘制入口**：骨架/porting-guide §7 写 `extractBackground`，`javap net.minecraft.client.gui.screens.inventory.AbstractContainerScreen` 显示容器面板实际由 `extractContents` 画，`extractBackground` 是 `Screen` 的变暗层。移植按 javap：`GuiContainerBase#extractBackground` 先 `super`（变暗）再画面板与组件的 background 层，`extractLabels` 画组件 foreground 层，`extractRenderState` 画组件的 `draw`，`extractContents` 末尾把悬停组件的 tooltip 交给 `setTooltipForNextFrame`（顺序与 1.12 的 background→slots→foreground→hover tooltip 一致）。
2. **`ContainerBase` 新增 `quickMoveStack`**：1.12 的 `ContainerBase` 没有 `transferStackInSlot`（各菜单自己写），26.3 该方法是 abstract，因此提供通用实现（机器槽在前、玩家 36 槽在后）。
3. **`InventoryWithSlots#getSlot(int)` → `getSlotHandler(int)`**：26.3 `Container#getSlot(int)` 同名且返回 `SlotAccess`，无法重载同签名；1.12 的调用者只有类内部（`ContainerLaunchBase#getSlot(0)` 是 `Container#getSlot`），改名不影响语义。
4. **`InventoryWithSlots#setSize`/`Size` 存档键删除**：26.3 容器定长，长度由机器代码决定（1.12 会按存档里的 `Size` 扩容）。
5. **`setChanged()` 的容器级语义**：1.12 `ItemStackHandler` 没有容器级回调，owner 只通过 `withChangeCallback((slot,stack)->markDirty())` 收到槽位级通知；26.3 容器级 `setChanged()` 用槽位 `-1` 上报，避免再加一个 owner 钩子（已在实现的 javadoc 中写明）。
6. **1.12 `FaceRotations.CW_FACE` 的排布**：1.12 的字面量按注释里的 "UP, DOWN, NORTH, SOUTH, WEST, EAST" 假设书写，但其枚举顺序（可由 `BlockLauncherBase` 的 `getFront(meta - 1)` + "default should be UP" 注释证明为 DOWN=0、UP=1）从 DOWN 开始，于是 `CW_FACE[DOWN]` 拿到的是 `CW_UP_AXIS`（UP/DOWN 两面的旋转表互换）。26.3 枚举序同样是 DOWN,UP,NORTH,SOUTH,WEST,EAST，移植按序数把每张轴表放回它所属的面；仓库内证据只能确定 DOWN/UP，WEST/EAST 谁在 4/5 未定，本写法在两种可能下都正确。
7. **`TextInput` 焦点守卫**：1.12 的 `setFocused` 在 `super` 之后用 `isFocusedIn == this.isFocused()` 判断（此时恒真，整段焦点处理是死代码），移植改为与调用前状态比较，使“失焦时解析并上报”这一 1.12 意图真正生效（否则 S5.03 的坐标输入无法提交）。SDL 焦点通知仍由 `super.setFocused` 完成（javap 已核实 `EditBox#setFocused` 调用 `Minecraft#onTextInputFocusChange`）。
8. **`BlockICBM#dropInventory` 未移植**：`affectNeighborsAfterRemoval` 运行时方块实体已被移除（`LevelChunk#setBlockState` 的调用顺序），方块层拿不到库存；26.3 的事实标准是 `BlockEntity#preRemoveSideEffects`（默认掉落 `Container` 内容）。需要掉落的机器在自己的方块实体里覆写该钩子并调用 `InventoryUtility.dropInventory`（S5.02+ 使用），已在 `BlockICBM` 的 javadoc 写明。
9. **`IGuiTile`**：保留接口名与包，但 26.3 的服务端菜单契约是 `ExtendedMenuProvider<BlockPos>`，因此改为继承它并默认 `getScreenOpeningData(player) = getBlockPos()`；1.12 的 `getClientGuiElement` 在 main 源集不能存在（黄金规则 4），客户端屏幕由 S5.03 用 `MenuScreens.register` 绑定。
