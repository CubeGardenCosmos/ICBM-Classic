## 实现要点

- **防御模式**（`RadarDefenseMode`）：`OFF` / `EMP_ONLY` / `ABM_ONLY` / `ABM_THEN_EMP`（默认 `ABM_THEN_EMP`）。
  `ABM_ONLY`/`ABM_THEN_EMP` 才驱动 `FireControl`；`EMP_ONLY`/`ABM_THEN_EMP` 才广播 EMP，且仅当存在
  `ticksToImpact <= ConfigAbm.EMP_FALLBACK_TICKS` 的航迹（`empTargets()`）。`OFF` 仍输出威胁红石。
  存档键 `defense_mode`；客户端同步 `PACKET_DEFENSE_MODE`（`nodeInt` + ordinal 范围校验）与 `PACKET_GUI` 的 `nodeEnum`。
- **渲染点**：`RadarRenderData`/`RadarRenderDot` 增加 `status` 字节，客户端按状态着色（DETECTED 绿 / THREAT 黄 / ENGAGED 红 / INTERCEPTED 灰）。
- **配置**：设计 §3 的 18 个键全部落位并有读取点；`AbmGuidance` 的硬编码常量（`BOOST_TICKS`/`BOOST_SPEED`/`MAX_TURN_RADIANS`/`REACQUIRE_RANGE`/`REACQUIRE_TIMEOUT_TICKS`）已删除并改为读 `ConfigAbm`。`flight_speed` 由裸 `final` 改为 `@ConfigEntry`。
- **`use_missile_target_data`**：`TileRadarStation.doScan()` 中为真且导弹 target data 有效时，`predictedImpact` 取目标坐标，`ticks` 仍由外推给出（设计 §5）；无有效目标时回落原外推路径。
- **配方**：`ICBMRecipeProvider.missileSpecials()` 按 1.12 `special/missile.anti_ballistic.json`（`c`=`basic_circuit`、`e`=`condensed_explosive`、`m`=`missile_module`，pattern `c/e/m`，产出 1）。生成物经 `runDatagen` 落盘。

## GameTest 实体可 tick 区域约束（重要）

**测量结论**：`Level#isPositionEntityTicking(pos)` 与 `LevelChunk#getFullStatus() == ENTITY_TICKING` 严格一致
（26.3 无 `LevelChunk.isEntityTicking()` 方法）。测试结构原点所在区块被标记为 `ENTITY_TICKING`，
**其外仅 `BLOCK_TICKING`/`FULL`**，因此位于其外的实体**不被 tick**（`inLevel=true`、`removed=false`、
`tickCount` 停滞）。`@GameTest(padding=…)` **只扩大测试空间，不扩大实体 tick 半径**（已用网格探针证伪）。

**由此产生的后果**：结构原点在不同运行的对齐差异会让同一份测试代码时绿时红——这是本项目
GameTest 间歇性失败的主要来源，与业务逻辑无关。

**处置**：所有参与 tick 的实体（ABM、目标、威胁导弹及其飞行路径）必须约束在原点区块内
（实测 `local ≈ -1..16` 为 `ENTITY_TICKING`，实用上取 `|local| ≲ 6`）。涉及远距离的场景只能使用
S4.03 的「区块外模拟导弹」非实体路径。

**force-load 证伪**：`ServerLevel#setChunkForced(int,int,boolean)` 确实能让被强制加载的区块在
票据成熟（约 20 tick）后进入 `ENTITY_TICKING`，但在 GameTest 夹具中使用会让测试服在
`GameTestInfo.tickInternal` 抛 NPE（`Object2LongOpenHashMap` 迭代器 `wrapped=null`）。
**结论：GameTest 中不可用**，不得作为扩大实体活动范围的手段。
