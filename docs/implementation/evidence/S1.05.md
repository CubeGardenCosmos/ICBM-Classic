## 与步骤卡的差异

- **`ITriggerActionMessage#onTriggerCallback` 签名**：1.12 参数为 `IActionStatus`；`IActionStatus` 属 S1.08（尚未移植），
  按澄清改为 `IRadioTargetAssignable`，javadoc 注明 26.3 移植期差异（S1.08/S7 再对齐）。
- **`RadioTile.ensureRegistered()/unregister()` 的接收器判定**：`RadioTile` 本身（同 1.12）不实现 `IRadioReceiver`；
  只有其子类（`RadioCruise`/`RadioScreen`/`RadioEmpTower`）是接收器，`RadioRadar` 仅为发送器。因此两方法用
  `this instanceof IRadioReceiver` 守卫后再调 `RadioRegistry.addOrUpdate`/`remove`，行为与 1.12“只登记接收器”一致。
- **`RadioRegistry.INSTANCE`**：1.12 仅用于 Forge `@SubscribeEvent` 注册，已随事件改写删除（新入口直接挂 Fabric 事件）。
- **`Channel` 过滤位置**：1.12 中 `RadioMap.popMessage` 不比较频道，频道过滤在接收器的 `RadioTile#canReceive`/`onMessage`；
  本步保持一致，GameTest 接收器自实现该过滤。
- **`GeneralCodexs`**：按 1.12 同路径移植；`PacketCodexTile` 的新构造签名需要显式 `Class<T>`，故工厂传入
  `IRadioChannelAccess.class` / `Radio.class`；`markDirty()` → `setChanged()`。
