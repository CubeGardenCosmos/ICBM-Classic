## 与步骤卡的差异

- **执行中断与接手**：原执行 Agent 在完成 41/42 个文件后被上游模型配额（429 GoUsageLimitError）中断；由我补齐 4 个 `config/util` 类、注册表查找工具 `RegistryLookup`、6 项测试、入口接入、账本/总目录/证据与全部验证。未使用 git stash 或回退，工作区保持连续。
- `ConfigManager#backupBroken`：原实现 `Files.move(..., REPLACE_EXISTING)` 在同分钟内覆盖既有备份；改为在同一时间戳后追加 `-1`、`-2` 序号寻找空位，不再覆盖。
- `config/util/**`：1.12 的 `@meta` 语法（方块/物品 metadata）在 26.3 已不存在，`BlockStateConfigList`/`BlockStateConfigListOld`/`ItemStackConfigList` 的 meta 分支改为解析物品/方块本体并 `LOGGER.warn` 提示“26.3 无 meta”，行为退化为默认状态（账本说明列同步记录）。
- `config/util/**`：1.12 的 `ResourceLocation` 键改为 `namespace:path` 字符串（配置 DSL 的 `~` 模糊标记不是合法 `Identifier` 字符，无法直接用 `Identifier` 承载）；仅在注册表查找时才 `Identifier.tryParse`。`ForgeRegistries.BLOCKS/ITEMS` → `RegistryLookup`（惰性解析），`Loader.isModLoaded` → `FabricLoader.getInstance().isModLoaded`。
- `BlockReplacementData#applyNBT`：1.12 的 `TileEntity#writeToNBT/readFromNBT` 在 26.3 不再公开，改用 `BlockEntity#saveCustomOnly(ValueOutput)` + `TagValueInput#loadCustomOnly`（javap 已核对为 public），保留 1.12 的“剥离 id/x/y/z 再合并”逻辑。
- `JsonToNBT` → `TagParser.parseCompoundFully`（异常为 `CommandSyntaxException`）。
- `ConfigJEI`：整类删除（账本 `DROPPED（ADR 0006：JEI 联动不在本轮范围）`）；1.12 里引用 Mekanism/IC2 的配置条目本次移植内容中未复现（对应 `mods/**` 本身已 DROPPED）。
- 未变更：CONFIG_CLASSES 共 13 个类（13 个 JSON 文件），字段名/默认值/静态性与 1.12 一致。
