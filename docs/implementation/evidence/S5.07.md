## 结果

- 基座：加载导弹作为 `ItemStackRenderState` 提交，位置按发射方向偏移，并使用 `RenderMissile` 的共用旋转变换。
- 巡航发射器：移植模型的 yaw/pitch 关节与持有导弹物品模型均通过提交管线渲染。
- EMP 塔：coil/electric 方块模型经 `BlockModelResolver` 准备并通过 `BlockModelRenderState#submit` 旋转提交；假结构块从主塔读取插值旋转与充能状态。
- 所有 `icbmclassic` 方块实体类型均有注册 renderer（静态模型类型注册显式空 renderer），新增自检在资源加载完成后遍历注册表；保留 S4.07 实体自检实现不变。
- 完整构建成功，GameTest 共 138 项全部通过。

## 与步骤卡的差异

- 使用 Fabric `BlockEntityRendererRegistry.register`，不用步骤卡示例中的私有 vanilla 注册入口；这是已复核的公开 API，不需访问改写。
- 为所有纯静态模型方块实体注册显式 no-op renderer，以满足逐个检查所有本模组类型的自检要求；只有卡片指定的基座、巡航发射器与 EMP 塔实际绘制动态内容。
- 巡航方块实体原有 `currentAim` 为 `protected`，为了跨 client 包读取显示角度，仅在其主源类增加 `getCurrentYaw()` / `getCurrentPitch()` 访问器；main 未引入客户端类型。
- 未移植 `TESRCruiseLauncher#debugMissileRotations` 的开发诊断球体网格（GL 调试工具，不属于目标行为）；主渲染路径已迁移到提交管线。
- 将物品模型提取/提交和导弹旋转变换抽成 `RenderItemImp` / `RenderMissile` 共用静态 helper，块实体 renderer 与 S4.07 复用同一路径。

## 未覆盖 / 已知限制

- 本环境无图形客户端；构建不执行客户端启动自检，也没有自动客户端渲染测试。turret/missile/EMP 的实际画面和自检日志需要图形客户端人工确认。
- 未修复 1.12 TODO「导弹按发射台光照渲染偏暗」，按步骤卡保留正常方块实体光照提交。
