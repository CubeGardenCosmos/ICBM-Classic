## 与步骤卡的差异

1. **`IcbmLookups` 增补 `MISSILE_STACK`（`ItemApiLookup<ICapabilityMissileStack, Void>`，id `icbmclassic:missile_stack`）**：步骤卡 §1 的骨架只列了 6 个 lookup。但 1.12 的 `MISSILE_STACK_CAPABILITY` 被本步删除后，`ICBMClassicHelpers.isMissile(ItemStack)`、`IMissileHolder#hasMissile/#consumeMissile` 以及 S4.02/S4.06/S5 的物品侧导弹查询就没有任何 26.3 对应物（S1.07 的目标是“所有 1.12 Capability 有 26.3 对应物”）。`ItemApiLookup.find(ItemStack, C)` 与 1.12 的“每个栈一份 capability 实例”语义一致，故按 §2.6 对 `IEMPReceiver` 的同款做法补上该 lookup，而不是让 `isMissile(ItemStack)` 返回假值。若验收方认为必须严格 6 个字段，请指示后可由 S4.02 改接 DataComponent。
2. **`MissileChunkEvent` 切断 content 依赖**：1.12 带 `content.missile.tracker.LoadedChunkPair` 与 `ForgeChunkManager.Ticket`（api 不得引用 content；26.3 无 Forge 区块管理器）。改为 `Identifier dimension` + `ChunkPos chunkPos` + 可变 `int timeLeft`，`Load`/`Unload` 各带自己的 Fabric `Event` + `Callback`。**S4.03 需在触发点自行管理区块票据并在事件后回读 `timeLeft`**。
3. **`api/events/**` 的 Fabric 化形态**：步骤卡 §2.1 只给了一行骨架，未规定数据如何传递。这里采用“事件对象承载数据 + `public static final Event<Callback> EVENT` + `@FunctionalInterface Callback`（可取消的返回 `boolean`，任一监听器返回 false 即取消）”，与原 1.12 `@Cancelable`/字段语义一一对应；抽象基类（`BlastEvent`、`EmpEvent`、`LauncherEvent`、`MissileEvent`）只作数据载体，`Event` 建在具体变体上（`BlastBuildEvent`、`EmpEvent.EntityPre/…` 等）。原 1.12 事件的构造参数改为回调参数。
