## 结果

步骤卡“操作”1–5 与“完成判据”逐条对应：

1. `EntityGrenade`（落地）：满足。继承 `Entity`；`motionX/Y/Z`→`getDeltaMovement()/setDeltaMovement`、
   `rotationYaw/Pitch`→`setYRot()/setXRot()` + `yRotO/xRotO`、`setLocationAndAngles`→`snapTo`、
   `ticksExisted`→`tickCount`、`onUpdate`→`tick`（`super.tick()` 前置于 1.12 的 `super.onUpdate()` 位置）、
   `canBeCollidedWith/canBePushed`→`isPickable/isPushable`；引信走
   `EX_GRENADE_REGISTRY.getFuseTime/tickFuse`，到时调 `explosive.doExplosion(...)`（`CapabilityExplosiveEntity`
   →`IExplosiveData#create(...).doAction()`，即 ICBM 爆炸物工厂）；无任何 `proxy.spawn*` 调用。
2. `ItemGrenade`：满足。`onPlayerStoppedUsing`→`releaseUsing(ItemStack, Level, LivingEntity, int)`，
   `getMaxItemUseDuration`→`getUseDuration(ItemStack, LivingEntity)`，`onItemRightClick`→`use` +
   `startUsingItem`，`getItemUseAction`→`getUseAnimation`（`ItemUseAnimation.BOW`）；创造标签沿用
   `ModCreativeTabs#acceptAll(EXPLOSIVE_GRENADES)`（S2.05 已接），tier 提示用既有键
   `icbmclassic.tooltip.misc.tier` / `icbmclassic.tier.*`（无新增键）。
3. `EntityBombCart`：满足。继承 26.3 `net.minecraft.world.entity.vehicle.minecart.MinecartTNT`；
   `ignite()`→覆写 `primeFuse(DamageSource)`（`super.primeFuse` 后再用 ICBM 引信覆盖）；私有的
   `fuse` 无公开 setter，按步骤卡加 `@Accessor` Mixin `icbm.classic.mixin.MinecartTNTAccessor`（已登记进
   `icbmclassic.mixins.json`）；`explodeCart(double)`→覆写 `explode(DamageSource, double)`（跑 ICBM 爆炸物工厂）；
   `killMinecart`→覆写 `destroy(ServerLevel, DamageSource)`；`getDefaultDisplayTile`→
   `getDefaultDisplayBlockState`（按爆炸 id 取 `ModBlocks.EXPLOSIVE_BLOCKS` 的平铺方块 + `FACING=UP`）；
   `getCartItem()`→`getPickResult()`（客户端用已同步的物品栈，1.12 客户端能力栈来自 spawn data）。
4. `ItemBombCart`：满足。`onItemUse`→`useOn(UseOnContext)`，照 `MinecartItem#useOn` 的写法判定铁轨
   （`BlockTags.RAILS`）、坡度偏移（`RailShape#isSlope`）与 0.0625 高度，放 `EntityBombCart` 并把物品栈传给能力。
5. `ModEntities` 注册：满足。`GRENADE`（0.25×0.25、4 区块/5 tick）与 `BOMB_CART`（0.98×0.7、4 区块/2 tick）
   均取自 `docs/architecture/registry-ids.md` §4（1.12 `EntityReg` 的 50/5 与 50/2）；尺寸来自 1.12 构造器
   （`EntityGrenade#setSize(0.25,0.25)`、`EntityMinecartTNT` 继承的 0.98×0.7）。
6. `ExplosiveFormItem` 形态改真实类：满足。`ModItems#registerFormItems` 改走 `createFormItem`，
   GRENADE→`ItemGrenade`、BOMB_CART→`ItemBombCart`（构造签名仍为 `(Identifier, ExplosiveForm, Item.Properties)`），
   其余形态保持 `ExplosiveFormItem`（MISSILE/BOMBLET 行为未动）。
7. `IcbmLookups`：不适用。手雷/炸弹矿车在 1.12 没有 EMP 或其它 lookup（grep `legacy-1.12` 的 `EntityGrenade`/

## 与步骤卡的差异

- **爆炸原因（cause）**：1.12 `triggerExplosion`/`explodeCart` 传 `new EntityCause(this)`。`EntityCause` 属 S4.01
  （实施期间正由并发 Agent 创建），为避免与并发改动竞争编译，本步按既有 `EntityExplosive#explode` 的写法传
  `null` cause 并留 `TODO(S4.01)`，与仓库现行约定一致（`EntityExplosive`/`EntityExplosion` 同样待补 cause）。
- **客户端同步**：步骤卡只说“删掉/留 TODO 的 proxy 调用”。1.12 用 `IEntityAdditionalSpawnData` 发送爆炸物物品栈，
  26.3 改为 `SynchedEntityData` 的 `DATA_RENDER_STACK`（`ITEM_STACK`），服务端由 `setItemStack` 写入；
  这同时是 S4.07 渲染与炸弹矿车 `getDefaultDisplayBlockState()` 需要的数据。
- **`getExplosiveData()` 实现位置**：1.12 用 `explosive.getExplosiveData()`（能力内从物品栈解析）。本步为让客户端
  也能解析，统一从“已同步的物品栈”经 `ICBMClassicHelpers.getExplosive(ItemStack)` 解析，找不到时回退 `CONDENSED`
  （与 `CapabilityExplosiveEntity#getExplosiveData` 的回退一致）。
- **`CapabilityExplosiveStack.fromStack` 扩展（跨步共享改动）**：扁平手雷/炸弹矿车物品不是 `BlockItem`，1.12 的
  物品能力（`EXPLOSIVE_CAPABILITY`）在 26.3 由 `fromStack` 代替，故补一条 `instanceof ExplosiveFormItem →
  getExplosiveId()`。纯新增分支，不改签名；`ItemMissile`/`ItemBombDroplet` 落地后自动受益。
- **炸弹矿车引信门控**：`super.primeFuse` 会先按 26.3 原生 `TNT_EXPLODES` 游戏规则判定，因此该规则关闭时 ICBM
  炸弹矿车不会起爆（1.12 的 `ignite()` 无此门控）。这是 26.3 原版矿车的既有行为，保留并在账本记录。
- **1.12 遗留存档分支删除**：`readEntityFromNBT` 里“NBTConstants.EXPLOSIVE 为旧数值 id”的兼容分支按 ADR 0002
  删除（不迁移 1.12 存档）。
- **`entityDropItem` 覆写删除**：其 1.12 作用只是让“掉落 TNT 方块”变成掉落本车物品；26.3 的掉落路径直接是
  `getDropItem()`（返回本爆炸物的扁平物品），该覆写无对应物。
- **`handleWaterMovement()` 删除**：26.3 `Entity` 无该方法（水流由 `Entity#move` 内部处理），1.12 的覆写本来
  就是对原版实现的照抄。
- **Client datagen 名称（跨步共享改动）**：注册了两个实体类型后，`ICBMLanguageProvider` 的
  `ENTITY_NAMES` 缺失会让 `runDatagen` 的校验直接抛异常，故在该文件补 `grenade`/`bomb_cart` 两行英文名
  （datagen 属开发期工具，不是运行时 client 代码；未改任何渲染/客户端入口）。已跑 `runDatagen` 再生成。
- **实体渲染器**：`IcbmEntityRenderers` 目前没有 grenade/bomb_cart 的渲染器，客户端自检会 `LOGGER.error`
  （S4.07 的既定缺口，该步的验证就是靠这条日志）。本步未在 client 注册渲染器（越界且属 S4.07）。

## 未覆盖 / 已知限制

- 未在图形客户端实机验证手雷投掷手感、矿车外观与粒子（无图形环境，人工门禁 S5.12/S4.07）。
- 炸弹矿车的 `primeFuse` 依赖 26.3 的 `TNT_EXPLODES` 游戏规则；GameTest 用默认开启。
- 未覆盖：手雷在水中的运动粒子只在客户端可见（`Level#addParticle` 客户端才真正生成，与既有 `EntityFragments`
  写法一致）；`EntityGrenade`/`EntityBombCart` 的 EMP 响应（1.12 本就没有）。
- 未跑 `bash scripts/check.sh` 的末尾 `./gradlew build` 段（其为工程级验证，由主 Agent/验收 Agent 统一跑）；
  本步单独跑了编译三目标、runGameTest、`check_lang.py` 与 check.sh 的前两段禁用名/客户端 import 扫描。
- 最后一次 `runGameTest`（105/105）跑在 `EntityBombCart#getPickResult` 收尾小修**之前**；该小修（客户端改用已同步
  物品栈）只做了编译验证，它不落在任何 GameTest 的断言路径上。
