## 结果

- 完成判据「`./gradlew build` 运行 JUnit 与服务端 GameTest，任一失败则构建失败」：满足。
  - 绿色路径：`Task :runGameTest` → `All 2 required tests passed :(` 的反面即 `passed :)`；`Task :test` → JUnit 1/1 通过；`BUILD SUCCESSFUL`，退出码 0。
  - GameTest 失败路径：`runGameTest FAILED` + `BUILD FAILED`，退出码 1，错误信息含我们注入的字符串。
  - JUnit 失败路径：`test FAILED` + `BUILD FAILED`，退出码 1，报告 `UnitSmokeTest > idUsesModNamespace() FAILED`。
- 完成判据「成功、故意失败两种情况都符合期望，并记录在证据中」：满足，三类日志均已原样记录。
- `gametest*` 配置名按实际输出确认存在（`gametestCompileOnly`、`gametestAnnotationProcessor` 生效：编译通过且 Lombok 配置无须改名）。
- `Identifier` 在 JUnit 环境可直接使用（无需引导 Minecraft 注册表），未触发步骤卡中的回退方案。

## 与步骤卡的差异

1. 步骤卡说“确认 `build` 依赖它（`runGameTest`）；若 `build` 不依赖它，追加 `tasks.named('check') { dependsOn 'runGameTest' }`”。实测 Loom 1.18.3 + `configureTests` 已把 `runGameTest` 接入 `check`/`build`，**未**追加该依赖。
2. 步骤卡写 JUnit BOM 为 `5.14.4`（经 S3.01 同机证据确认存在），照用。
3. GameTest 计数为 2（其中一个来自 Fabric/原版默认测试集），我们的用例 `icbmclassic-test:smoke_game_test_stone_can_be_placed` 在失败日志中按名出现，确认已注册并执行。
