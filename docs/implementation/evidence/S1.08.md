## 与步骤卡的差异

1. **`ActionField` 重设计（步骤卡要求，写进证据）**：1.12 的 `ActionField<VALUE, TAG extends NBTBase>` 依赖
   `Function<VALUE,TAG>`/`Function<TAG,VALUE>`；26.3 改为 `ActionField<VALUE>`，save/load 直接在给定 key 上操作
   `ValueOutput`/`ValueInput`（`ValueWriter<V>`/`ValueReader<V>` 函数式接口，可空）。内部 `Map<String, ActionField<?>>` 按 key 去重，
   同 key 不同类型抛 `IllegalArgumentException`（与 1.12 一致）。`ActionFields` 条目按 26.3 重写：float 用 `putFloat/getFloatOr`、
   `Vec3`/`Direction`/`Identifier`/`CompoundTag` 用对应 `CODEC`、Boolean 用 `putBoolean/getBooleanOr`；`HOST_ENTITY` 保持
   “不可存档”（save/load 为 null，与 1.12 一致，javadoc 注明可加网络传输）。`ActionDataBase` 的字段表由 `serializeNBT/deserializeNBT`
   改为 `ISavable.save/load`（键结构保持 `fields` 列表 + 每项 `key`）。
2. **网络传输延后**：步骤卡要求“字段的存档用 SaveHandler，网络用 FriendlyByteBuf”。本步只做存档，未给 `ActionField` 加
   `StreamWriter/StreamReader<FriendlyByteBuf>`——本步没有任何 `IActionFieldProvider` 走网络的路径（Codex 未覆盖字段系统），
   现在加会是无调用方的死代码。**网络传输在 S3（爆炸动作实际联网/同步）接入时补**；不破坏编译，`ActionField` 的
   save/load 接口已预留可扩展点。若验收要求立即补齐，请指示。
3. **`ActionProvider.register()` 不调用**：1.12 该方法只做 Forge capability 注册（`CapabilityManager.INSTANCE.register`），
   26.3 无 capability 机制，`ActionSystem.setup()` 原调用点改为 `TODO(S1.07/S1.10)` 注释；`ActionProvider` 保留为
   `IActionProvider + ISavable` 的普通类型，挂接方式待 S1.07/S1.10 用 API Lookup / 数据附件确定。
4. **content 注册延后（范围裁决）**：`ACTION_REGISTRY` 建空表 + 事件 + `lock()`，`ActionDataEmpArea`(S3.07)、`ActionDataCluster`(S4)、
   `ActionSpawnEntity`(S3.05) 注册处留 `// TODO(Sx.yy)`；`ACTION_CAUSE_REGISTRY` 只注册 `CauseByTimer`，`EntityCause`/
   `CausedByBlock`/`RedstoneCause`(S4)、`BlockScreenCause`(S5) 留 TODO；`ACTION_STATUS_REGISTRY` 不注册 `LauncherStatus`(S5，留 TODO)。
5. **A 方案（主协调者裁决）**：`content/missile/logic/source/{ActionSource, cause/ActionCause, cause/CausedByBlock}` 与
   `lib/data/LazyBuilder`、`lib/tile/ITick` 提前到 S1.08。理由：`CauseByTimer`（步骤卡 §6 要求移植）必须继承 `ActionCause`，
   `PotentialActionImp`（§5 要求移植）必须构造 `ActionSource` 并用到 `CausedByBlock` 的 `BlockEntity` 便捷重载。这 5 个类自包含
   （只依赖 api + lib/saving），S4 直接复用、无需返工；账本步骤列写 `S1.08（S4 复用）` / `S1.08（S2.02/S4 复用）`。
   `EntityCause/RedstoneCause/BlockScreenCause` **未**移植。
6. **`ActionSource`/`CausedByBlock` 的维度处理**：1.12 用 `int` 维度 id + `DimensionManager.getWorld` 惰性解析；26.3 无全局世界查找，
   故新增 `dimensionKey`（`Identifier`）字段（`@Data` 生成 getter/setter），`ActionSource` 用 `SaveRoot#nodeWorldDim`（S1.03 提供）
   写 `level.dimension().identifier()`，`CausedByBlock` 保留 1.12 键名 `level` 但改存 `Identifier` 并新增 `pos`/`state` 不变。
   调用方（S4）在只有存档时需要自行用服务器把 `dimensionKey` 解析回 `Level`。
7. **`ICBMClassicAPI` 仅动作字段**：只含 `ID`、`CONDITION_REGISTRY`、`ACTION_REGISTRY`、`ACTION_POTENTIAL_REGISTRY`、
   `ACTION_STATUS_REGISTRY`、`ACTION_CAUSE_REGISTRY`、`ACTION_LISTENER`；类 javadoc 注明 missiles/explosive/projectile/
   capabilities/refs 由 S1.10/S2/S4 追加。账本行状态标 `PORTED`（步骤列 `S1.08、S1.10`，说明列写明剩余字段来源）。
8. **5 个注册事件的 Fabric 化**：删除 Forge `Event` 继承与构造参数，改为
   `public static final Event<Callback> EVENT = EventFactory.createArrayBacked(Callback.class, listeners -> registry -> {...})`，
   回调方法得到对应 `IBuilderRegistry`；`ActionSystem` 用 `EVENT.invoker()` 触发后 `lock()`。原事件类的“构造器参数”语义改为回调参数。

## 未覆盖 / 已知限制

- **`MetaTag` 保留 1.12 的 `TAG_MAP` 行为**：1.12 `getOrCreate` 用 `find(namespace + ":" + path)` 查询、却用 `TAG_MAP.put(path, metaTag)`
  写入，因此同名 tag 不会真正去重（每次 `getOrCreate` 生成新实例并重复挂到父节点）。按“行为等价优先、移植步不修旧 bug”保留；
  各类型常量均为 `static final` 单例，`isAssignable` 的身份比较在实际使用中不受影响。若后续需要全局唯一 tag 需单独立项。
- **`IActionStatus#isError/isBlocking` 的 `@deprecated` javadoc 无 `@Deprecated` 注解**：编译产生 2 条 `[dep-ann]` 警告（1.12 同样写法）；
  未加注解以保持与 1.12 一致，不影响构建（非 `-Werror`）。
- **`PotentialActionImp.doAction(BlockEntity, IActionCause)` 的 `level` 可能为 null**：1.12 假设方块实体已挂世界；26.3 `BlockEntity#getLevel()`
  可空，本步按 1.12 语义直接解引用（与旧行为一致），未加空判。
- **未在图形客户端验证**；动作系统为服务端逻辑，无客户端代码。GameTest 未覆盖 Fabric 注册事件的第三方注册路径（事件已 `invoker` 触发，
  但无监听器注册用例）；未覆盖 `PotentialAction`/`ActionProvider` 的存档往返（其 `SaveHandler` 依赖注册表内条目，S4 接入内容后测试更合适）。
- **`ActionProvider`/`PotentialActionKnown` 无使用方**：均为框架类型，待 S4/S5 内容接入。
