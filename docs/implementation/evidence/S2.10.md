## 1. datagen 生成的英文名（146 键）

`ICBMLanguageProvider` 只生成能从注册表推导的键：

| 键 | 数量 | 取值 |
| --- | --- | --- |
| `block.icbmclassic.<id>` | 32 | 见下表 |
| `item.icbmclassic.<id>` | 83 | 见下表；**方块物品不重复生成**（`RegHelper.blockItem` 用 `useBlockDescriptionPrefix()`，物品复用 `block.*` 键） |
| `icbmclassic.explosive.<id>` | 25 | 基础英文名 |
| `icbmclassic.form.<form>` | 5 | `%s Explosive` / `%s Missile` / `%s Grenade` / `%s Bomb Cart` / `%s Bomblet` |
| `itemGroup.icbmclassic.main` | 1 | `ICBM-Classic` |

## 4. `mergeLang`（build.gradle）

- 输入 `src/main/generated/assets/icbmclassic/lang/en_us.json`（生成，146 键）+ `src/main/resources/assets/icbmclassic/lang/en_us.json`（手写，260 键），
  输出 `build/generated/lang/assets/icbmclassic/lang/en_us.json`；同键不同值 → `throw new GradleException("lang key conflict: " + key)`。
- 两个源目录里的 `en_us.json` 被 `sourceSets.main.resources.exclude` 排除，`processResources` 与 `sourcesJar` 都
  `from(build/generated/lang)`，所以 jar 里只有一个英文语言文件。
- 生成文件缺失时（从未跑过 `runDatagen`）打印 `mergeLang: … is missing, run runDatagen to generate it` 并只合并手写部分，
  避免「datagen 依赖 processResources → 死锁」；此时 `LangGameTest` 会因为键缺失而失败，不会被静默放过。

## 与步骤卡的差异

1. **排除方式**：步骤卡写「`processResources` 排除两个源中的 `en_us.json`」，实现改为
   `sourceSets.main.resources.exclude`。原因：`processResources.exclude` 会同时过滤掉随后 `from()` 加入的合并文件
   （实测合并文件没进 `build/resources/main`，两个 GameTest 因此失败），排除必须落在源目录上。
2. **`sourcesJar` 也要同样的替换**：默认 `withSourcesJar()` 会把两个源都打进去 → `duplicate entry` 构建失败，
   因此 `sourcesJar` 同样 `from(build/generated/lang)`。
3. **生成文件缺失不报错**（打印 lifecycle 提示）：否则 `runDatagen` 在从未生成过的仓库上会因 `mergeLang` 失败而永远跑不起来；
   由 `LangGameTest` 兜底。
4. **检查 7 支持「前缀字面量」**：`"icbmclassic.tier." + getSerializedName()` 这类拼接无法用步骤卡给的正则判全键，
   实现为「以 `.` 结尾时要求至少一个键以该前缀开头」，否则报错。
5. **字幕值取 1.12 原文**：1.12 本来就有 16 个 `subtitle.icbmclassic:*` 键，S2.09 的自拟英文在 S2.10 被迁移结果覆盖
   （例如 `subtitles.icbmclassic.antimatter` = "Antimatter Explosion"），避免自造字符串。
6. **`rot`/`mutation` 的英文名由 ID 派生**（1.12 无内容因而无名字），其余 23 个爆炸物都取 1.12 原文。
7. **`item.icbmclassic:held_item_missile.sword.name` 按运行时文本迁移**（不在生成范围），其余 `.name` 全部由 datagen 生成。
8. **`block.icbmclassic.*` / `item.icbmclassic.*` 的 meta 后缀不进新键**：1.12 的 `concrete.0/1/2` 等已平铺为独立方块
   （ADR 0002），迁移规则里同名键只用于判断「是名称键」，不产出新键。

## 未覆盖 / 已知限制

- 只有 `en_us`：其他语言的 7 个 `.lang`（de_DE/es_ES/ko_KR/pt_BR/ru_RU/zh_cn）留给 S8（`check_lang.py` 已能检查 3/4/5/6 项）。
- `check_lang.py` 的第 4 项在 S8 之前只警告；第 5 项按 i18n.md §3 只比较编号集合，不比较 `%s`/`%d` 的类型。
- `icbmclassic.tier.none`（`EnumTier.NONE`）在 1.12 也没有对应键，原样保留（该枚举值的 `getLocalizedName()` 会返回键名）。
- 迁移文件里 S4/S5/S6 的键（发射台、雷达、协调器、工具提示等）目前没有代码引用，属「已迁移未使用」，
  对应步骤接入时直接按 `scripts/lang_key_map.json` 查表。
- `entity.icbmclassic.*` 尚未生成（当前没有注册实体类型）；S4/S7 注册实体时必须补 `ICBMLanguageProvider` 的名字表，
  否则 datagen 抛异常。
- `mergeLang` 只做「键合并 + 冲突报错」，不检查占位符或空值（由 `check_lang.py` 负责）。
- 生成的 `en_us.json` 键顺序由 datagen 决定（手写文件是字典序）；jar 内是合并后的字典序。
