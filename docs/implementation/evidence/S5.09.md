## 结果

- Grenade and bomb-cart behaviors now subclass `DefaultDispenseItemBehavior` and override the javap-verified `execute(BlockSource, ItemStack)` method. The base behavior provides the dispenser sound and animation after behavior execution.
- Grenade motion preserves the 1.12 facing vector, vertical component `0.10000000149011612D`, speed `0.5F`, and inaccuracy `1.0F`; it spawns at `BlockSource.center()` and carries one copy of the dispensed explosive stack.
- Bomb carts preserve the 1.12 rail-in-front / air-in-front-and-rail-below placement checks, slope height offsets, 1.125 directional spawn offset, and custom name. Non-rail targets fall back to the base default item dispense.
- Registration is placed directly in `ICBMClassic#onInitialize`, immediately after `ModEntities.register()` and before `ModMenus.register()`. This keeps the call in the documented initialization sequence and needs no extra registry class.
- The two legacy behavior classes do not depend on another behavior helper; no additional legacy source file was required.
- The ledger entries are `PORTED`, both assigned to S5.09; S5.09 catalog status is `[R]` with this evidence link.
- Verification: `All 143 required tests passed :)`; `BUILD SUCCESSFUL`.

## 与步骤卡的差异

- The card’s test sketch requested grenade firing; the test suite additionally covers bomb-cart rail placement because its legacy placement rules differ materially from default dispensing.
- Dispenser behavior registration is inline in `ICBMClassic#onInitialize` rather than a dedicated registry class, following the existing single-entrypoint registration structure.
- The legacy grenade behavior contains no explicit sound or animation calls; the 26.3 default behavior superclass supplies its standard dispenser sound/animation. The legacy bomb-cart fallback delegates to its default behavior, represented by `super.execute(...)` in the subclass while the outer default behavior performs the sound/animation once.
- No `LevelEvent` or custom `SoundEvent` mapping was needed: neither legacy behavior class contains explicit `world.playEvent` or sound calls.
